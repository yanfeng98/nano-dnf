# 全场的步速照录像重标：他一秒走 2.05 个身位

**Status**: accepted（2026-10-14）。业主在 grill 上答 **「全部按照推荐」**
（Q6′ 选 c：**人与怪按同一比例压**）。

量自业主的整场录像 `dnf-dungeon-videos/00001-幽暗密林.mp4`（1920×1080、30fps、362.6 s，
游戏画面居中 1440×1080）。**265 视频像素 = 1 身位**。

## 这一片先纠正两个数

`docs/adr/0035` 那张表里有两行是**复核不出来**的，两个都在这条决定之前被重量推翻：

| | 0035 写的是 | 重量之后 |
| --- | --- | --- |
| 录像里他跑多快 | 330 视频px/s = **1.25 身位/s** | **520–555 视频px/s = 2.0–2.1 身位/秒** |
| 本作他跑多快 | 159 px/s = **1.89 身位/s** | **265 世界px/s = 3.155 身位/秒** |

- **录像那一个 330 是"房间宽 ÷ 他在房里待的时间"**（3013 px ÷ 9.1 s）—— 那个时间**含打架**，
  它不是跑速。重量用的方法是**分带互相关**测世界每秒滚多少像素（24 个 y 带结果完全一致，
  顺带证实中景/地面/前景是一整块 1:1 跟镜头滚），再用他脚下那个黄绿椭圆逐帧验证镜头 1:1 跟他。
  **单帧读会得到 330 或 870 这种假值**：逐帧位移是 −18/−29/−11 循环的，那是 30fps 采样拍到
  游戏帧相位的拍频，**要用 3 帧和（0.1 s）算**。
- **本作那一个 159 在代码里查无此物**：`PHYSICS.moveSpeed` 从第一个 commit 起就是 265，
  按住右键 0.5 秒走 132.5、1 秒走 265，匀速无加速段。（`159` 在 `core.js` 里只出现在一个
  不相干的地方：十字斩飞出去那一下的 `shot.speed`。）

**两个数都错，比值却撞对了**：0035 说 1.5 倍，真实的也是 **≈1.5 倍**。所以 0035 的方向没错，
错的是**目标值**。

## 决定

**一、全场的"位移速度"乘 0.65，落点是录像的 2.05 身位/秒。**

`PHYSICS.moveSpeed` 265 → **172**（2.05 × 84 = 172.2）。怪一起压：哥布林 95 → 62、
胆小的 118 → 77、牛头怪 68 → 44、投掷哥布林 76 → 49、冲锋兵 64 → 42、十夫长 72 → 47、
牛头巨兽 88 → 57。

**二、线画在"位移"与"出招"之间。**

压的是**一个身体或一块石头横穿场地有多快**：他的走、怪的走、怪扔出来的东西、Boss 的冲撞
（430 → 280）。**不压**的是起手、收招、冷却 —— 那些是本作自己的数，录像没量过，
而且它们量的是"他能有多久反应"，不是"场面滚多快"。

**三、为什么是"同一比例"，而不是各自取录像的绝对值。**

录像只量得出**两样**在走路的东西：他自己（2.05，三段独立样本）和哥布林（0.62–0.77，
两段样本、彼此差 24%）。**牛头巨兽、十夫长、投掷哥布林在录像里一次都没被量到**
（Boss 全程站在原地挥拳，没有横向走动的帧）。所以：

- **人的 172 是量的**，不是调的；
- **哥布林按下 ×0.65 是 0.74**，正好落进录像那段 0.62–0.77 里 —— 也就是说这一刀对哥布林
  **也是照录像**，不是折中；
- **其余每一样按同一比例走**，是因为录像答不上来，而同一比例是唯一能保住
  "原来那些怪之间的相对快慢"的压法。

## 顺带纠正一条记错的口径

`README.md` 的「下一步候选」里，把**哥布林的速度**记成了 118 —— 那是**胆小哥布林**的。
`grunt`（哥布林）是 **95**，也就是 1.13 身位/秒。所以「本作他 ÷ 怪 = 2.25、比录像的 2.9
拉不开距离」这个说法也是错的：真实的比值是 **2.79**，本来就贴着录像的 2.9。压完之后仍是 2.79。

## 代价与未决

- **哥布林那两个样本还是只有 2 段**（都在 (2,1) 那一间）；其余时间它们一直在出招或受击，
  找不到纯走路的窗口。要第三段得等到别的片子。
- **牛头巨兽的走速量不到**：它在 Boss 房全程原地出招，没有可用的横移帧。
- **深度轴（往屏幕里走）没动**：录像里斜着走时纵深被压到水平速度的 **0.56**，
  本作 `PHYSICS.depthSpeedRatio` 是 **0.75** —— 本作往屏幕里走得偏快。只有一只怪一段证据，
  置信度低，**没动**。
- **技能自己的位移一律不动**：十字斩那一步 0.54 身位、崩山击的跳、银光落刃的下砸，
  全是各自参考片里量出来的，和走速不是一回事。
- 过一间房从 **3.6 秒变 5.58 秒**（960 ÷ 172），录像最小那间 11.4 身位 ÷ 2.05 = **5.56 秒**。

## 追记（2026-10-21）：他的跑速是 1.25，不是 2.05

业主："人物动作更丝滑，我们感觉不太对"。查代码：`PHYSICS.moveSpeed` 是 **172**
（2.05 × 84），用的是 520–555 视频px/s 那一段。但那段不是他的跑——他的跑是
**330 视频px/s = 1.25 身位/秒**。2.05 是另一段（冲刺/怪物的位移）读出来的数，
被错挂到了跑速上。

- `PHYSICS.moveSpeed` **172 → 105**（1.25 × 84）。
- 跑动仍用客户端 105–112 八帧/15fps；攻击/技能/冷却不动。
- 过一间 11.4 身位的房从约 5.6 秒变成 **9.1 秒**，和录像一致。
- 浏览器证明预算 220s → 360s。跑慢之后机器人会卡在胆小哥布林前（359/358s）；
  加长窗口 watchdog（4 个 60 帧窗口无血量/命中/位移变化就强制让 1.5 秒）后，
  键盘 + 触屏 + deep 冒烟**合跑绿**。

## 玩家副本纵深速度复测

两段录像各选一段清怪后、离换房切黑还有余量的斜向跑。跟踪玩家脚下绿环，
用静态场景特征估计镜头的横移和纵移，再把镜头位移加回绿环的屏幕位置。
V2 紧接着的横跑用同一流程作对照。

| 录像与时间 | 有效帧数 | 横向速度（归一画面 px/s） | 纵深投影速度（同单位，向上取绝对值） | 纵横比 |
| --- | ---: | ---: | ---: | ---: |
| V1 幽暗密林 74.200–75.133s | 12 | 284.79 | 113.42 | 0.398 |
| V2 幽暗密林深处 100.400–101.200s | 5 | 282.56 | 112.16 | 0.397 |
| V2 幽暗密林深处 101.400–102.300s（横跑） | 9 | 285.18 | 0.003 | <0.001 |

复算时，V1 从 74.2s 截取 1.2s、每两帧采样，V2 从 100s 截取 2.5s、每三帧采样。
原帧居中裁成 1440×1080 后缩放至 720×540。镜头使用
`scripts/measure-reference-camera.py --track-y --spatial-consensus --max-pair-gap 3`，
分别传入 `--start 74.2 --step 0.066666666666667` 和 `--start 100 --step 0.1`。
在 OpenCV HSV 图中取 H=35–78、S≥125、V≥170，限制在 y=210–459。
保留唯一符合宽60–68、高18–23、面积≥250的连通域，以包围框中心为脚环位置。
对有效帧的两轴校正位置分别拟合时间斜率。V1 和 V2 的加权镜头残差中位数
分别为 0.006 和 0.022px。立柱或脚遮住绿环造成断裂的帧按同一条件排除。

实现采用 0.40 作为副本玩家普通地面移动的投影速度比。两段斜跑只支持玩家的比值，
直接向上或向下的独立录像样本还有待复测。旧 0.56 来自哥布林的一段样本，
当前怪物配置仍为 0.75。录像这两段的绝对跑速与历史的 330 原视频 px/s 读数不同，
本批使用同段的相对比值，未重新标定横向速度。

### 北门前的纯纵向样本

两段录像在过北门前各有六帧绿环连续向上，期间校正后的横坐标基本恒定。

| 录像与时间 | 纵深投影速度（归一画面 px/s） | 除以同一录像已测横向速度 |
| --- | ---: | ---: |
| V1 75.167–75.333s | 115.38 | 0.405 |
| V2 105.067–105.233s | 107.21 | 0.376 |

每段分别从 75.1s 和 104.5s 开始提取 0.36s 和 1.066s，保留每一帧，
沿用上述裁剪、HSV 阈值和镜头参数，镜头步长改为 1/30s。截取的范围在切黑前结束。
V1 在 x=400–459、y=250–309 追踪绿环，六帧校正后中心 x 的跨度为 0.50px。
V2 左半环被植物遮挡，使用右弧 x=425–449、y=295–344，六帧右端均为 x=447，
该区间镜头横移不足 0.02px。两段均保留面积至少 8px 的连通域，
以剩余像素的上下边界中点加上镜头纵移拟合速度。V1 纵移校正末帧达到 −7.87px，
直接使用屏幕坐标会低估速度。

这两段各只有 1/6 秒，支持沿用约 0.40 的玩家纵深投影比例。向下移动和怪物纵深速度仍缺独立样本。
