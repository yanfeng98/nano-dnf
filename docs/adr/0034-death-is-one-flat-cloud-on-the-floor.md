# 死是一团**贴地的白云**：没有倒地、没有圆爆、没有碎块

**Status**: accepted（2026-10-11）。业主实玩完 `0031`/`0033` 那一片之后说的是
**「现在怪物死后和视频依旧不一致」**；我把重量的结果摆出来（录像里找不到彩色碎块），
他在三个选项里选了**「完全照录像」** —— 碎块与圆爆整条删掉。

## 上一片错在哪

`docs/adr/0033` 把死写成**两段**：尸体先躺 0.2 秒 → 白烟盖住它、烟散一起没 →
**同时**炸出十二块按怪自己颜色染的碎块，落地后在草上留 2.6 秒。

那一条的依据是业主一句口述 —— 「原视频是变成肉块，绿色的怪物是绿色的，黄色的是黄色」。
**口述被当成了一帧**：整段是从这句话里读出来的，不是从画面里量出来的。同一句口述里
"肉块"到底指什么也没再问。

## 这一片量的

量的是业主 2026-10-11 给的**整场录像**（`dnf-dungeon-videos/00001-幽暗密林.mp4`，
1920×1080、30fps、6:02），主样本是 96.63–96.97s 的一次击杀（绿哥布林，画面上 108 px 高），
再用 245.9s 的蜥蜴怪与 328.4s 的 Boss 各复核一遍：

| 量到的 | 数 |
| --- | --- |
| 怪怎么没的 | **当场没** —— 96.633 还站着，96.667 就没了（≤1 帧） |
| 云的样子 | 一片**贴地、实心的白**；包围盒 **276 × 114 px** = **2.6 × 怪高宽、1.05 × 怪高厚** |
| 云在哪 | 上缘高过脚线 **0.44 怪高**、下缘低 **0.61**（脚 y≈837，云 y[790..903]） |
| 实心程度 | 阈值 190 与 232 量出来的面积一样（16.4k / 17.2k px）——**几乎全不透明** |
| 动 | **不上升**：包围盒 96.667–96.900 一动不动，动的是里面的形状 |
| 活多久 | **0.30 秒**：96.667 满 → 96.933 缩到 45% → 96.967 没了 |
| 之后留下什么 | **什么都不留**（三处现场都没有圆爆、碎块、血迹） |

Boss 是同一件事的放大版：一大团白云约 0.9 秒，一样不留东西。

## 决定

1. **怪死的那一帧就没了**，云同时起来 —— 没有倒地那一段。云在 `damageEnemy` 里推，
   `updateDeaths` 只负责把死人从 `state.enemies` 里拿掉（以前烟和尸体共用 `enemy.dying`
   一条时间线，谁先谁后是有讲究的，现在没有了）。
2. `DEATH = { cloud: 0.3, bossCloud: 0.9 }`；`lie` / `smoke` / `burst` / `chunks` /
   `chunkCount` 五个数删掉。
3. 渲染改成**把客户端那片云横着摊平、叠几遍**：那张 `monsterdieblood` 云片自己是软边的
   （alpha 均值 107、只有 16% 的像素是实的），盖一遍出来是烟不是云 —— 所以 9 片横铺、
   每片叠 4 遍、每次挪一两个像素，中段才实。量出来的结果和录像对得上：
   **155 × 67 px（我们要 161 × 66）**，阈值 232 下的面积 7.4k（录像折到我们的屏幕是 5.6k）。
4. `chunk_<type>{0,1,2}`（十八个矩形）与 `deathBurst` 从 `src/render.js` 的 `SCENE.pieces`
   里删掉。**`assets/forest.png` 里那几块烘着的像素还留着** —— 这台机器上没有客户端，
   重烘不了；下次带着客户端重跑 `assets/import_dnf_scene.py` 时可以一并去掉。

## 后果

- **`0033` 的第二段作废。** 第一段（"地上不留东西"）方向对，但"烟盖住尸体"也不准确 ——
  尸体根本没留到云起来的时候。
- 这是第二次**业主指定的偏差被同一把尺撤掉**（第一次见 `0013`）。两次的教训一样：
  **口述是线索，不是证据；动手前先把那句话在画面上找到。**
- 抓帧工具：`tests/browser/capture-death.mjs`（把页面的 rAF 时钟接管过来，一格一格走，
  每帧记 `dying` / 场上的效果），量图用小脚本数"最大的一块近白像素"。
