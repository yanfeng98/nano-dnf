# 清房不再发强化卡；删卡的余量用基础数值补

**Status**: accepted（2026-10-18）。业主原话：

> 「我不想要通关每一个房间给的加buffer的奖励」

## 决定

**整条「每清一间房 → 三选一强化卡 → 加一种属性」的回路删掉。**

- 清房只做三件事：`room.cleared` / `cell.cleared`、`stats.rooms += 1`、门口亮起来。
  **门在清房那一刻就开**，没有「选完卡才放行」。
- 删掉 `UPGRADES`、`UPGRADE_ORDER`、`UPGRADES_PER_ROOM`、`rollUpgradeOptions`、
  `offerUpgrade`、`chooseUpgrade`、`state.upgradeChoice`、`player.upgradesTaken`。
- 选卡 UI、触屏/键盘 1–3、标题演示的选卡段、`upgrade` 提示、结算表里的「强化」行
  一起删；`hints.js` 的门提示只再看 `room.cleared`。
- **保留**：XP/等级、地上掉落与自动拾取、血之狂暴的血球、技能自己的 buff、
  失败/通关结算里其余各行。

它和等级是两套系统：卡只改 `attackBonus / maxHp / mpRegen / skillPower /
attackSpeed`，战斗逻辑从不读 `upgradesTaken`；`localStorage` 的战绩只存
时间/等级/通关次数，不存卡，所以**没有存档迁移**。

## 代价与补偿

- **同种子的后续随机流会变**：原来每间房发牌要消耗三次 `nextRandom`。没有保留
  「空抽三次」——那道抽签只服务于已经不存在的卡池，留着是替死代码维持轨迹。
- **难度上升**：同一套 bot 在四个种子上的承伤从 38–67 抬到 62–121 / 156–176。
  2026-10-18 实机证明里浏览器 bot 会在第 9 格或领主房被磨死。
- 因此补基础数值，**不是把卡偷偷加回来**：
  - 玩家基础生命 `120 → 176`（满级上限 `156 → 212`）；
  - 领主生命 `260 → 120`；
  - 领主近战 `18 → 13`（二阶段 ×1.2 后 15.6）、重踏 `20 → 15`；
  - 牛头怪（重甲）近战 `13 → 11`。
- 量法：浏览器证明键盘/触屏两条通路都能通关，领主战仍要躲重踏、贴脸仍会挨打；
  只是不再需要靠卡池的数值堆过去。

## 追记（2026-10-18）：领主倒下即通关，不用再清剩下的怪

业主复看：「dnf杀死领主后会有一个特效，并且就通关，不需要再次杀死其他任务」。

原来 `resolveRoom` 要等 Boss 房 `alive.length === 0` 才胜利，领主倒下后还得把
同房的小怪补掉。现在：

- 领主一 `dead`，`resolveRoom` 就把其余小怪从 `state.enemies` 里拿掉，只留领主；
- 领主的**白色剪影**继续演 `DEATH.lie + bossSmoke`，这期间世界照常推进；
- `state.victoryDelay` 到 0 才立 `victory`，所以死亡特效先被看见，再进胜利页；
- 这期间 `resolveRoom` 不放他出门（防止从 Boss 房门口走掉）。

总击杀数的口径跟着改了：**Boss 房只数领主**；其余走过的格子仍然要清光。浏览器证明
允许"领主房小怪在领主倒下前先被杀掉"的那一档（`expectedKills` 到 `maxKills`）。

## 追记（2026-10-20）：两批怪之后，领主 120 → 100、玩家 176 → 200

每间房加了第二批怪（`docs/adr/0037` 追记三）之后，浏览器证明的键盘与触屏两条通路
都出现过**最后一两下倒地**：一次在领主 8/100 血时（领主一刀 13，玩家只剩 6–8 血），
一次在两只胆小哥布林前。两处都补基础余量：

- **领主 120 → 100**：让"先退再打"的读法在加怪之后仍然成立；
- **玩家基础生命 176 → 200**：只补基础值，不是把强化卡加回来。

浏览器证明的机器人也一并修了两处**量法**：技能的命中距离按
`reach + target.width / 2` 算（以前拿中心距对 138 宽的领主，几乎一个技能都放不出），
并且领主最后 12% 血时优先用无敌技收尾。

这是**为了证明可玩性**的余量，不是把 Boss 做软 —— 觉得太软就回调这两个数，
同时把浏览器证明的机器人策略一起看。

## 追记（2026-10-21）：深处片之后的余量 200 → 220、100 → 90，以及机器人的转身

在做 幽暗密林深处（`docs/adr/0059`）的片子里，浏览器证明的合跑反复红：一次在
**领主 2 血**、一次在 **6 血**时玩家倒地；另两次是机器人卡在一间两只
`咒之赤哥布林` 的房里，`want=down`/`want=attack` 转了 220 秒。两件事分开办：

- **机器人（测试侧）**：只剩杂兵/被逼到墙角/领主最后 12% 这三个"提前还手"的分支
  原来在通用的"攻击只打到面朝那一边"检查之前，冲过头以后会朝反方向一直挥空。
  现在这三个分支都先转身；再加一条**连续 90 帧没有位移、又不在出招/受击**时
  横向让一步（必要时跳）的防卡死。游戏本身没加寻路。
- **基础余量（游戏侧）**：玩家基础生命 **200 → 220**、幽暗密林领主 **100 → 90**。
  这是给"机器人能稳定把最后一下换出去"的余量，和深处那只 150 血的猫 Boss 无关；
  觉得太软就回调这两个数，同时把机器人那三处转身一起看。

改完 `npm run test:browser` 连跑两次键盘 + 触屏 + deep 冒烟均绿；这不是把怪改弱，
是让"先退再打"在机器人 20ms 的输入节拍下也成立。

## 追记（2026-10-22）：技能/受击停顿之后的余量 220 → 240

补技能命中停顿（`docs/adr/0061` 追记）之后，浏览器证明又红了两次，但都不是领主：

- **键盘通路**在胆小哥布林那间站错深度、一刀刀挥空（实测 z 差 97、26 秒没掉血），
  总伤害从 122 涨到 224 —— 这是机器人策略的缺陷，修在 `playability.mjs`（被杂兵
  追打时先走排对齐再还手；领主房里小怪在房间另一头时不横穿领主去追）。
- **触屏通路**在咒之赤哥布林前 **4 血**倒下，总伤害 222。同一份代码键盘通路是
  **198 血**收的，差的只是两条通路的输入节拍。

**玩家基础生命 220 → 240**。给两条通路留同样的余量，和上面几次是同一套做法：
不是把怪改弱，也不是给玩家加新机制。觉得太软就回调这个数，同时把机器人那两处
策略一起看。改完 `playability.mjs`（键盘 + 触屏）与 `deep-smoke.mjs` 分别单跑绿
（这台机器一次一核）。
