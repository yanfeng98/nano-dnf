# 地图界面 = 客户端的地图块 + 一条蜿蜒的路，常驻右上角

**Status**: accepted（2026-10-09）。业主在 grill 上：**「Q1a也要」**（要跑图时右上角那张，
不是进关前那屏选关地图）、**「Q2选择a」**（不做私服那层壳）、
**「q3你要做的一样，不要就是五个房间一字排开」**，其余按推荐。

## 决定

**一、这张图常驻右上角。** 不按键、不弹出：录像里它从进关第一帧就在，而且它承担
"这一关我走到哪了"的读数。参考片是 `assets/dnf_src/bilibili/BV1d24y1P74G.mp4`
（幽暗密林，56.9–332 秒都在画面上；50.5–53.8 秒那屏全屏选关地图**不做**）。

**二、一格一块客户端的地图块，1:1。** `sprite/map/minimap/act1.img` 有 122 帧，
**一帧就是一个格子**：一个房间（一坨）或一条穿过的走道（一条线），加几个朝向邻居的短接头。
烘制在 `assets/import_dnf_minimap.py`，产出 `assets/minimap.png`。

- **客户端不告诉你哪帧是哪格**（那在加密的 `Script.pvf` 里），所以脚本**量**出来：
  墨迹是地图那种卡其色、脚下是蓝通道低得多的绿；四个边中点说这一格通哪几个方向；
  一行够宽的墨迹说明是房间而不是走道。`--table` 打印出来的那张表就是 `src/render.js`
  MINIMAP.tiles。
- **用暗的那一族，不是亮的那一族。** 两族墨迹的红分量是 103–110 与 145–163；录像里
  **整张图从头到尾都是暗的**（90 秒与 250 秒两次采样房间中心，都是 112–119）。
- **录像点到哪一帧就用哪一帧**：把每帧缩放到录像自己的格距（40.5 px）滑窗比，
  冠军 RMSE 6.3–8.0、亚军 10.9 以上，于是房间 E=#0、房间 N=#8、房间 W=#24、
  走道 NS=#72 / ESW=#96 / SW=#88 / NSW=#104 / NEW=#48 这几帧是**录像自己用的那几帧**。

**三、格子是 4×3，路是一条**楼梯**。** 客户端的两出口房间**只有 {东,南} 与 {北,西}**
两种形状，所以任何一条只用现成形状铺出来的路都只能一路向西再向南（`src/core.js` MINIMAP）。
四条模板，由种子选一条；`state.minimap.cells[i]` 就是第 i 间房。

**四、两副形态，一个键。** 默认是方形窗口（录像里占 99% 的时间），`Tab` 或点角上那枚 ⊘
换成**圆盘雷达**（同一张图裁成圆盘、跟着人放大居中，录像开头那 20 秒的样子）。
`Tab` 在这里被 `preventDefault` 吃掉：不然浏览器会拿它去走页面自己的链接，
下一次回车就把链接按了。

**五、窗口本身也是客户端的。** 那圈边框是 `sprite/interface/minimap.img` 的 #27–#35
（**九宫格**，在旧客户端 `ImagePacks2_70/sprite_interface.NPK` 里，新客户端没有这个包）；
它的中间那格是一片 50% 黑（α=128），压在一块棕色上——录像里标题条那口暖褐 `(57,48,39)`
正是客户端 `(98,84,60)` 砍了一半。老板的红头恶魔脸 #37、玩家的蓝色小柱、圆盘那圈象牙齿环，
都是从同一张图集里切出来的。
**只有 ⊘ 是画的**：客户端有那枚按钮的底面、没有那个符号（每个 interface 包都扫过）。

## 为什么必须这么做

**"和录像一致"这件事，量得出来。** 窗口在录像里是 79×75 客户端像素，格距 18——
本作的角色与客户端同高（84 屏幕像素 对 约 80），所以 **1:1 就是同一个大小**，
整张图落在 81×79 上。颜色也是量的：房间卡其 `(112,116,47)`、boss 红 `(233,74,0)`、
玩家蓝 `(25,194,255)`、标题条 `(57,48,39)`。

**"五个房间一字排开"是业主否掉的**（原话）。图上的拐弯是真的拐弯：路怎么走，
图就怎么画，`cells[i]` 与 `state.layout[i]` 逐位对上——**五个房间一字排开时它才是一排**。

## 被它推翻的

- **HUD 的右上角原本是房间卡片的**（`drawHud`，`x = width - 236 - 16`）。卡片左挪，
  让出角上这块地方。
- **触屏那三枚按钮（音/编/停）占着右上角**，所以**触屏模式下这扇窗往下落 60 px**
  （`MINIMAP.touchTop`），否则它们压在一起。

## 代价与未决

- **路是一条链，不是一张网。** 录像里的地图是**分叉**的（同一行能左右走、下面还挂着两间房），
  那是 DNF 的跑图真有岔路。本作的跑图是顺序的五间房（`docs/adr/0026` 第四节），
  所以图上画的也**只能**是一条链——它每一格都走得到，但看起来比参考稀疏。
  **要真岔路，就得改跑图**，那是另一片。
- **4×3 的格子里只用了 5 格**，剩下 7 格是空格。客户端**没有空格这一帧**
  （act1 每一帧都带房间或走道，因为录像那张图每格都有东西），所以空格是从"未知房"那帧
  把问号抹掉得来的（`blank_cell()`，只抹中间那个方框，四角原样留着）。
- **圆盘那副形态**在录像里是**压在方形窗口底下**也还露着的（同一个大圆环一直在画面上）。
  本作只在自己那一副里画它——这是有意的，那更像是那个客户端自己的叠加方式。
- **地图块的路径名（`act1`）里的"act 1"就是格兰之森**，所以另外 7 关**形状够了、编号还不知道**：
  真要给它们各配一张，得再找 `act2/act3/…` 里去。
