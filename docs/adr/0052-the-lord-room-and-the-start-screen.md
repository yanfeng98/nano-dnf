# 领主房的牛头、启动加载屏、开始画面的音乐

**Status**: accepted（2026-10-17）。三条都来自业主这一句：

> 「右上角的地图，领主房间，应该是牛头图标；还有就是游戏启动，开始时加载的角色和怪物
> 是像素和老的怪物，请你修复成现在的角色和哥布林牛头的；游戏开始的音乐请你也改掉」

## 一、领主房：牛头从第一帧就画

图标**不换**：客户端 `sprite/map/minimap/minimap.img` 的 `(358,288,16,14)` 本来就是
一张**红牛头**，专门为地图这一格画的，亮红、双角、轮廓清楚。

**试过、否掉的**：按推荐先做了一版"用牛头巨兽本体的脸"（`drawMonsterFace` 从
`monsters.png` 第 5 行切头）—— 抓帧一看，那张画在 18 px 下只剩一团棕色，角和
白鬃糊在一起，反而认不出是牛；选关卡片上那张正脸牛头缩小后也一样糊。**图标要的是
"一眼认出是牛"，不是"用的是本体那张画"**，所以留客户端标记。

**改的是它什么时候出现**：原来 `boss.seen` 为真才画（`docs/adr/0051` 那半条）。
可这张图对领主房的全部意义是**指路** —— 等他走进去了才画，等于只告诉他"你已经到了"。
现在**领主房不吃迷雾**：底下的格子没去过仍是黑的，**牛头从第一帧就露出来**。
这条**改了 `0051` 里「Boss 红脸也只在去过之后才画」那半条**；其余迷雾规矩不变。

## 二、启动：素材没到齐就画加载屏，不画后备画法

"开始时加载的角色和怪物是像素和老的怪物"不是另一套启动素材 —— 是
`main.js` 不等 `slayer.png` / `monsters.png` / `forest.png` 的 `onload` 就开始渲染，
于是走了老渲染器的后备画法：`drawFallbackPlayer` 的像素小人、`ENEMY_STYLE` 的方块怪、
`drawStoneBackdrop` 的石头地牢。图一解码完就换回客户端美术，但那一瞬间业主看见了。

现在：10 张图各记一次完成（`assets.ready`），**没到齐之前只画
`Render.renderLoading`** —— 它一个 `drawImage` 都没有，只有 LOGO、副标题与进度条。
到齐后才开始标题演示；加载屏上不接受任何游戏输入。图 404 也记作"到过"，
免得一张坏图把页面永远卡在加载屏（渲染器对缺图本来有后备）。

## 三、开始画面放客户端自己的 `intro.ogg`

原来是第一次按键就放 `mirkwood.ogg`（副本曲），标题页与进副本之间没有分界。
现在 `Music.TRACKS` 多一条 `title` → `assets/music/intro.ogg`（客户端原曲，
1:44.85，与另外两首同一个来路、同样进 git 并记出处）。

- **标题 / 地区地图 / 进副本那 2.34 秒过场**：`title`；
- **房间淡进来（`state.intro` 清掉）**：切 `room`（`mirkwood.ogg`）；
- **领主格**：仍是 `boss`（`mirkwood_boss.ogg`）。

第一次手势就开始放开始画面那一首（浏览器只允许手势后出声），所以标题页不再是一段静音。

## 代价

- 启动多等一次 10 张图的解码（合计约 8.7 MB；本地很快，慢网会更明显）。
- 领主房在迷雾里也可见：玩家还没探到那格就知道 Boss 在哪 —— 这是有意的，`0051` 的
  "没去过的是黑的"只对普通格子成立。
- 开始画面的曲子是客户端原曲，文件名与另外两首一样随客户端版本走。
