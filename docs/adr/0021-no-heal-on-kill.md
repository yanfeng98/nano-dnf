# 怪物死了不掉回血球

## Status

accepted（2026-10-04）。业主的原话：**「现在怪物死了有绿色的球，请你去掉」**，并在被问"去掉的是机制还是那颗球的样子"之后选了**整条去掉**。

## 决定

**击杀不再产出任何拾取物。** 第二切片那条"清怪掉回血球"整条撤掉：`spawnDrop`、`DROPS` 那一组常数
（`playerHeal 18` / `eliteHeal 30` / `bossHeal 42` / `gruntDropChance` / `orbRadius` / `lifetimeSeconds`
/ `gravity`）、以及渲染端那条绿球的画法一起删。`updatePickups` 里"落在地上的掉落物"那条分支
（重力、深度对齐那套判定）随之消失——**`pickups` 里现在只有血球**。

**这不是平衡调整，是把"血从哪来"这件事收归一处。** `0017`（accepted）写过「血球从此不是锦上添花，
是**唯一的续航**——形成'必须一直打才活得下去'的循环」，但 `DROPS` 一直在旁边发着 18/30/42 点的白送，
那句话从写下的那天起就不成立。业主这一句把它变成字面意思：**回血只有一个来源，就是开着架势打人。**

没动的是**升级回血**（`PROGRESSION.healOnLevelUp = 12`）——那不是一颗球，也不在业主说的那条线上；
要动它得单独说。

## 取证

- 那条绿球：`kind: "heal_orb"`，`#8dffb0` 的球 + 三倍半径的绿光，半径 13（屏幕上约 40px），
  从尸体上方弹出、受重力落地、走进 32px 内自动捡起，14 秒不捡消失。
  **它和这一版重做的血球几乎一样大**（球 40px），一绿一红并排站着——这是业主看见它的那一眼。
- 各档回血量是固定值而不是比例：18 / 30 / 42，对 120 上限就是 15% / 25% / 35%。Boss 那一颗等于三分之一个血条。
- **机器人证明不受影响**：整局承伤 7（键盘）/ 0（触屏），本来就没靠这些球活着。

## Considered Options

> **保留机制，只换掉那颗绿球的样子**（改成血色雾气，或击杀当场跳一行 `+18 HP`）。否，业主选的是整条去掉。
> 顺带说明为什么"保留机制但不画球"是行不通的：它是**走进去捡**的，看不见就等于没有。
>
> **只去掉绿球的美术，机制继续跑**。同上——一个看不见的拾取物不是设计，是 bug。

## Consequences

- **不开血之狂暴就没有任何回血手段**（除了升级那 12 点）。这是有意的：架势的代价（`0020` 那张十秒一次的账）
  换来的是唯一的回血通道。
- **按种子重放的结果会变**：`spawnDrop` 从确定性随机流里抽过号（小兵掉落判定），少抽一次，
  它之后的每一次 `nextRandom` 都错位——包括回避掷骰与血球的 34% 判定。种子仍然可复现，**同一个种子不再等于同一个结果**。
  `killAll` 这个测试帮手因此改成"打到死为止"：它原来打一下就走，而精英与 Boss 有回避（`0018`），
  错位之后那一下正好会被闪开。
- **`README.md` 的两行会过期**：「掉落：精英必掉回血球…」与「拾取：走进回血球…」。
  按仓库规矩，等业主玩过点头之后再连同这一片一起改。
- **`DROPS.pickupRadius` 改成 `BLOOD_ORB.catchRadius`**：它现在只服务于血球"飞到他身上"这件事，
  不再是"地上的东西能被踩到多远"。
