# 门口清空、树石实心、缺口后面接草裙；同一身位时身体压在布景上

> **修正（2026-10-15，`docs/adr/0051`）**：这一条里那句「**贴花不在这套里：它们不挡人也不挡门**」
> 只管**走路**，不管**认路** —— 业主实玩时看到「有的花丛遮挡住门口了」。**门口那一块是给人
> 认路的**，花丛盖上去门拱就看不见了，所以贴花现在**也过「门口净空」那一关**。
> （12 格里 757 件不挡人的布景，压在门口的是 0 件。）

**Status**: accepted（2026-10-11）。业主在 `docs/adr/0031` 那一片的实玩之后报了五条，
grill 上逐条定掉，最后一句话又是**「全部按照推荐做」**：

1. 「原来黑色的地方，现在渲染的依旧不好」—— 上一片的补法做出来是一排竖条纹；
2. 「怪物死了，原视频是变成肉块，**绿色的怪物是绿色的，黄色的是黄色**，不是烟雾」；
3. 「怪物和石头的**图层**也不对」；
4. 「**门口不能有石头和树木**」；
5. 「**数目（树木）和石头也要有碰撞**」。

第 2 条是**推翻我自己上一片的量法**，单独在这一片的第五、六节写。

## 决定

**一、地面顶上的缺口后面接的是 mid 自己的草裙，不是补色，也不是竖条纹。**

客户端的 `mid` 那张图（`sprite/map/02mid0.img`）里**树根线在第 316 行，底下还有 63 行是草**
（裙边）；原版把地面条摆成"顶边压在根线上"，所以地面条顶上那些缺口（每张 224 列里有 217
列带缺口）**透出来的永远是那 63 行草**，绝不可能是空洞。本作把 mid 摆得比客户端高了这
一条裙边，缺口下面就成了没人画的地方。

- 上一片拿"缺口用它正下方的颜色填上"顶了急，业主一眼看出不对：**那是一排 1–13 像素宽的
  竖条纹帘**（整条地边 217/224 列都有，最深 40 像素）。
- 现在的做法：**把 mid 再铺一遍、裁到接缝以下**（`SCENE.midSkirt = 63`，`drawBackdrop`）。
  地面不透明的地方把它盖住，只有缺口里看得见 —— 看见的就是客户端自己那 63 行草。
- 顺手修了一个真 bug：**三张地面条的缺口天生接得上，但顺序不是 1-2-3** ——
  客户端那个循环是 **tile2 → tile1 → tile3**（tile2 末列 39/38/39 接 tile1 首列 40/39/38 ✓、
  tile1 末列 7/9 接 tile3 首列 6/8 ✓、tile3 末列 9/11 接 tile2 首列 9/7 ✓）。按 1→2→3 摆，
  x=672 那里留下的是 11→40 —— 屏幕上就是一道 30 像素的竖台阶，业主圈的那块里有它一份。

**二、立着的布景是实心的：树、树桩、石柱、石头挡人。**

`Core.SOLID` 这一张表（`docs/adr/0032`）：
`trunkTall / trunkBent / trunkMossy / treeLeafy / stump / pillar / wallStone / rockFlat / rockSmall`。
和木桶分家的地方只有两条：**打不碎**（挥击只认 `BREAKABLE`）、**不挡飞行物**（和木桶一致 ——
怪不会绕路也不会换排，挡了投石就等于把它们废掉）。

- **盒子只取贴地那一段**：把每件美术最底下 12 行的 ink 量出来（业主：「数目和石头也要有
  碰撞」—— 看得见的东西挡人），树冠、石头的上半截**不进盒子**（"看得见的树冠"和
  "走不过去的空墙"对不上就是 bug）。`width` 与中心偏移 `dx` 都是这么量的：
  `trunkTall 146/+4`、`trunkBent 111/+6`、`trunkMossy 100/−18`、`treeLeafy 84/−4`、
  `stump 74/−4`、`pillar 43/0`、`wallStone 163/−1`、`rockFlat 92/−20`、`rockSmall 42/0`。
- 深度没有像素可量（美术是正面的），按**宽的三分之一**给、钳在 24–40 —— 和木桶(52/34)同一档手感。

**三、门口净空：每扇门前面那条带里不许摆实心件。**

`blocksDoorway` 查**两种压法**，各用各的空间：

- **地面**：布景的盒子（x-z）压在"进出要用的那块地"上（左右门贴墙 `DOOR.side + DOOR.stand`、
  上下门是那一格自己的门 x 左右各 `DOOR.span + DOOR.stand`、深度加一个 `DOOR.stand`）—— 挡路；
- **美术**：布景的美术矩形（屏幕）压到**门拱自己**的美术盒子上（`gateArtRect`）—— 把门画糊。
  一棵 105x199 的树桩可以站在判定区**前面**（第一条查不出来）却把整个门拱盖掉 ——
  业主截图里的胆小鬼的窝、断桩隘口都是这一种。

压在带上的实心件**先往旁边挪**（12 像素一步、两边交替找最近的空位），挪不开才丢；只在
**摆位时**过、只在**按格**过，因为房间是按种子洗到格子上的，同一间房落在不同格子会碰上不同
的门（上门/下门的 x 是那一格自己的）。贴花不在这套里：它们不挡人也不挡门。

量出来的代价：默认种子十二格**一件不少**；种子 1 的十夫长的营寨会少一块石墙（那间房两头都
挤满了）。

**四、同一个身位时，身体压在布景上。**

`drawWorld` 的入队顺序改成**贴花 → 布景 → 掉的东西 → 怪 → 抛射物 → 他自己那几层 → 人**，
平局（同一个 z）时后入队的在上。以前布景排在怪后面，于是同一个 z 上**布景盖怪、人盖布景**
（业主报的「怪物和石头的图层不对」）—— 现在两边一致：**身位相同，站着的人赢**。

## 被它推翻的

- **`docs/adr/0031` 的第一条**（烘图时 `close_top_gaps` 用正下方的颜色补缺口）：整套撤掉，
  连 `close_top_gaps` 函数一起删。缺口的内容该由 **mid 的草裙**给，不该由地面自己糊。
- **`SCENE.ground = ["tile1","tile2","tile3"]`** → `["tile2","tile1","tile3"]`（量出来的循环）。
- **`CONTEXT.md` 的「道具」**：从"除木桶外都没有碰撞"改成三档（贴花 / 立着的实心件 / 木桶），
  并新增**「门口净空」**一条。
- **`blockProps` 只认木桶** → 认整张 `propBox`（木桶 + 立着的实心件），并带上 `dx`。

## 代价与未决

- **怪在录像里是会穿过布景的**（量过：155.0s 一只哥布林横穿木桶的落点，不减速、不绕、
  不被推回；150.75s 它站在石柱的剪影里被石头盖住），**本作让它撞**（业主点名要的）。
  所以本作比录像"更实"：怪会被树干挡住、顶着它推，摆位的人得避开小怪必经的那条线。
- **门口净空按格丢布景，所以同一间房落在不同格子上会少几件布景**（丢的是压门那一件，
  比如藤蔓窄道的桶 x=60 碰上有西门的那一格就没了）。这是"门口不能有东西"的代价。
- **树线挡在北门前面**：北门要走到房间最深处，而最深处站着一排树 —— 人和 bot 都得**先横着
  走到门的 x、再往里走**（演示与测试的 bot 因此都换了脚：`Core.routeStep`，一格 24 单位的
  BFS，绕开实心件）。玩家自己会绕，但这是新增的一层走位。
- **第 2 条（死亡）不在这一篇里**：它推翻了 `docs/adr/0031` 的第六节，整篇写在
  `docs/adr/0033`。
- 第 2 条「原视频是变成肉块，绿色的怪物是绿色的」**量下来业主是对的**（见 `0033`）：
  死是两段 —— 白烟盖住尸体，烟散那一刻炸成**它自己颜色的**碎块。


## 2026-11-08 追记：逐件倍率进入判定（第四十八批，待实玩）

`propBox(piece)` 原来只取种类的默认倍率，绘制却已经使用 `entry.scale`。
真实 `Core.step` 最小复现：岩石在(300,120)，人站(245,120)，岩石倍率依次
0.5、0.75、1，旧实现全部把人推至x217；移除岩石则保持245。
这是逐件倍率漏传，不是房间边界或倍率字段丢失。

`propBox`、`propArtSize` 增加可选绝对倍率；碰撞、寻路、近战/独立剑气命中、
布景生成与候选落点检查均传当前实例倍率。宽度、纵深和根部dx沿横向倍率，
高度沿纵向倍率。历史 `box` 碰撞系数按新/默认美术倍率同比变化，暂不推翻未获录像
证明的宝箱0.48碰撞系数；可见ink边界单独按美术倍率计算，避免把0.72的图误算为0.48。

五个定向回归覆盖空隙通行、真实接触、寻路、桶的远近命中和非等比边界。
同一最小复现修后分别保持245、推至233.5、推至217，证据见
`../reference-evidence/48-instance-collision.json`。这证明实例尺寸一致性，
不证明素材原始碰撞盒、宝箱HP/超宽纵深或录像隐藏规则；CB-07继续开放。
