# 可达距离量的是"身体之间还差多远"，不是两个中心之间

**Status**: accepted（2026-10-09）。业主让继续处理他自己列出的缺口，第一条就是
「Boss 的碰撞盒还是旧的」——而那条的根因不是数字没调，是**口径**。

## 决定

**凡是"够不够得着"，一律量 `bodyGap` = 两个身体沿 x 减去双方半宽**（碰在一起是 0，
叠在一起是负数）。`src/core.js` 的 AI 与命中判定全部改用它：
`attackRange`、`keepRange`、冲锋的起手、精英旋风的commit、Boss 的砸地与二阶段突进。

**每个数按它当年量时的那副身体一对一换算**（`新值 = 旧值 − (旧身体半宽 + 玩家半宽)`），
所以**玩家今天感受到的手感与换口径之前完全一致**：

| | 旧（中心距） | 新（身体外） |
|---|---|---|
| 哥布林 | 46 | **14** |
| 胆小哥布林 | 42 | **12** |
| 牛头兵 | 54 | **17** |
| 投掷哥布林 / 它的站位 | 210 / 150 | **178 / 118** |
| 十夫长（含旋风的commit） | 64 / 113 | **24 / 73** |
| 牛头巨兽（含砸地commit / 突进带） | 74 / 120 / 96–210 | **29 / 75 / 51–165** |

砸地是个例外，它**本来就是有边的**（一个摊在地上的圆盘）：`slam.radius` 保留"从圆心算"，
但**跟着身体长大**——Boss 从 56 宽长到 172 之后，它从 150 变成 **208**（= 身体外 105 + 新半宽 103）。

## 为什么必须这么做

**同一个改动，两种口径，结果是一个打不出伤害的 Boss。**
把牛头巨兽按客户端尺寸放大（`docs/granfloris-assets.md` 第六节：客户端把它画成约 3.2 个玩家高，
哥布林只有 0.85）之后，实测它被碰撞解算推开到 **189 px** 外，而它的 `attackRange` 仍是 **74**，
**它一下都打不出来**。根因是中心距离口径把**身体有多宽偷偷算进了可达里**：
身体每宽一 px，可达就少一 px。逐个去调那些数是治标——下一次改体型还会再犯一次。

换成身体间距之后，实测 Boss 的可达边界落在 **132 px 中心距**（= 身体间距 29 + 半宽 103），
与算式一分不差，而且**这个数不再随体型变化**。

## 连带改了什么

- **`ENEMY_TYPES` 的 `width/height` 现在既是碰撞盒也是画出来的尺寸**——两者合成一个数，
  因为口径换掉之后身体可以自由变大了（`src/render.js` 的 `MONSTER.draw` 因此删掉）。
  怪按客户端比例站在一起：哥布林 33×53、牛头兵 68×80、牛头巨兽 **172×201**。
- **两个 bot 都得跟着换尺子**（`tests/core.test.js` 的 `kitingBot`、`tests/browser/playability.mjs` 的
  策略）。它们原本拿中心距离去比可达，于是**走进牛头巨兽身体里面**——那正是策略掉血的来源
  （实测某一局 79 点伤害里 66 点出在 Boss 房）。现在两边都用 `bodyGap` 量、都按**自己的可达**
  决定停在哪儿。
- **测试里"把近战关掉"的老写法失效了**：`attackRange = 0` 以前等于"永远打不到"，
  现在等于"贴在一起才打得到"，而身体够大时就真的贴在一起。这些地方改用
  `tests/core.test.js` 的 `NEVER_REACHES`。

## 代价与未决

- 牛头巨兽的可达范围从 74 px 涨到 **132 px**，也就是**它的禁入区大了一圈**——这是必然的：
  客户端把它画得那么大，它的攻击本来就该覆盖那么大一片。**它现在明显更难打**，
  这一条要业主上手判。
- `slam.radius` 从 150 涨到 208（二阶段再 ×1.18），地上那个圆盘也跟着大了一圈。
- `body05`（与 `body02` 剪影差 0.10）与 `body07`（牛头王，差 0.32）**没有共用手上这套数字**，
  以后做那两关时要各自量一次。
