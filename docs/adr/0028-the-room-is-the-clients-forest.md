# 房间是客户端的森林（set 02），不是我们自己挑的那一套

**Status**: accepted（2026-10-09）。业主在 grill 上选「**Q1a也要，但是真正的是整个场景，
包括怪物树什么的**」，其余按推荐：(a) 底 + 道具、(b) 地图两种形态都做、交付清单只做
幽暗密林这一关的场景与地图。

## 决定

**幽暗密林每一间房的底图，是客户端自己的地块 set **02**，一条都不自己画。**
一套地块不是一个图层，是四层（`docs/granfloris-assets.md` 第三节）：

| 层 | 客户端条目 | 画在哪 |
|---|---|---|
| 远景 | `sprite/map/02far0.img` | 蓝雾山峦，`mid` 的树缝里透出来 |
| 中景 | `sprite/map/02mid0.img` | 那排紫蓝树干，底边压在地面带的后缘 |
| 地面 | `sprite/map/02tile01..03.img` | 从地面带后缘一直铺到屏幕底下（224 宽，横向平铺） |
| 道具 | `sprite/map/02obj*.img` | 树/石/花草/桶，由每间房的 `props` 点名摆放 |

烘制在 `assets/import_dnf_scene.py`（**每个条目裁到自己的墨迹**，落位由 `src/render.js`
的 `SCENE` 决定），产出 `assets/forest.png`。房间出口那扇石门是客户端的
`sprite/map/pathgate/granflorissidegate02.img`——家族号 02 就是这套地块自己的家族。

**道具只有美术，没有碰撞。** 它们走 `drawWorld` 那条按深度排序的路，所以一间房后缘的树干
画在怪前面、前缘的桶画在他后面，但谁都撞不到它们、它们也不打谁。

## 为什么必须这么做

**因为上一片把这一条**猜**错了，而且文档里写着是猜的。** `docs/granfloris-assets.md` 第四节
「建议地块」那一列注明"客户端里查不到，所以是我们的选择"，给幽暗密林挑的是 set **01**
（明亮阔叶绿林）。业主那段录像给了答案：幽暗密林房间里那排**紫蓝色、带橙褐树皮纹**的大树干
就是 `02mid0`，远景那片蓝雾山就是 `02far0`。**这不是口味问题，是同一个文件。**

**为什么不是"照着录像画一张"**：这套地块是 640 宽、横铺的分层图，房间多宽它都能铺；
照着一间房画一张死图，下一间房就得再画一张。

## 被它推翻的

- **`docs/granfloris-assets.md` 第四节**「幽暗密林 → set 01」那一格——已改成 02 并注明依据。
- **`src/render.js` 的 `drawBackdrop`**：它画的是石砖墙、飘动的拱门、三支火把、木板缝地面，
  那是那座已经删掉的地牢（`docs/adr/0026`）留在这里的最后一件东西。现在它画森林；
  石头那一版**改名 `drawStoneBackdrop` 留着**，只用于 `assets/forest.png` 还没加载完的那几帧。

## 代价与未决

- **另 7 关没有场景**：它们的 `rooms` 还是空的、根本进不去（`src/core.js`），配了也是白配。
  冰霜幽暗密林要 set 02 的 `f` 覆雪孪生（同形状加积雪），烈焰格拉卡要 set 04，
  这一条留给各自的切片。
- **桶画了但不能打**。客户端的 `barrel.img` 是一整套 13 帧（完好的 + 打碎的），本作只用了第一帧
  当布景。要能打就得有"可破坏物"这一层，那是玩法，不是美术。
- **`02obj` 一共 66 条（不含 `f` 孪生），只挑了 15 条。** 剩下的（枯树、断桩、蕨、地面碎石）
  是下一轮加房间时现成的料。
