# 普攻命中停三帧，第三下把人打倒，挥砍中的按键不吞

**Status**: accepted（2026-10-22）。业主第三次复看说「人物动作更丝滑，我们感觉不太对」，
在 grill 的 Q9 选 A：**先做普攻三连、受击/击倒/浮空、打击停顿；技能下一片**。
这一条只覆盖普攻；技能自己的停顿不在这里定。

## 背景

`docs/adr/0018` 把「打击感」和「硬直」分开了：硬直是自身属性，普攻挂永久僵直会变成控制；
要打击感「另起一条」。这一片就是那一条。

本作普攻已经三段（`ATTACK_STAGES`，第 0/7/16 帧起），受击、击退、浮空、击倒的字段也
都在 `damageEnemy` 里；怪挨打时的白闪与倒地帧（`goblin.down` / `rise`）在渲染里。
缺的是**命中那一下的停顿**、第三下自己的收尾反应，以及**挥砍中按下的那一刀不被吞掉**。

## 决定

**一、普攻命中冻结世界 3 / 3 / 5 帧（60fps），击杀 6 帧。**

- 停顿期间世界不推进（他、怪、伤害数字、镜头都停），**但 `state.time` 照走**：
  计时、配速线、连段窗口按真实时间算，不因停顿丢秒。
- 只有**他挥中的普攻**触发（`damageEnemy` 的 `opts.hitStop`）；技能、出血 tick、
  地板火不触发。技能的停顿下一片单独定。
- 冻结长度是本作的数：录像 30fps，2–5 个 60fps 帧在录像里只合 1–2 帧，量不准。
  交给他实玩后按手感调 `HIT_STOP`（秒，不是毫秒）。

**二、第三下把人打倒，前两下只推开。**

- 第三下 `knockdown: 0.6`、击退 220（前两下 140）；霸体不吃击倒 —— 和 `launch`
  同一条（`docs/adr/0018` 的「无法浮空」）。
- 击倒走渲染里已有的 `down` / `rise` 帧；浮空连段仍归 `juggle`，这一条不新增空中招式。

**三、挥砍中按下的普攻记 0.5 秒，不被吞掉。**

原来只有在收招段按才接得上；挥的那 0.22 秒里按下的会被丢掉，读起来是「连段没出来」。
现在挥砍中按下记进 `player.attackBuffer`，这一刀结束立刻起下一段；放技能/挨打清掉。
0.5 秒是**最长的一刀**（0.22 / `MIN_ATTACK_SPEED`(0.5) = 0.44 秒）再加一点余量：
只要是在这一刀挥完之前按的，就一定接得上。

## 为什么

**停顿是「这一下打到了」的触觉。** 60fps 下两三帧就够，多了会变成卡顿。世界冻结而不是
把怪变慢：两个人都停，才读得出「刀砍进去了」，而不是「怪被减速」。

**第三下要有自己的收尾。** 前两下都只是推开，三下读完还是同一档反应，连段的最后一下
没有落点；第三下把人打倒，玩家才有「打完一套」的收束。

**挥砍中的按键是连段本身的一部分。** 玩家按三下的节拍不会刚好落在收招段；吞掉中间那一下，
读起来就是「我明明按了」。

## Considered Options

- **只冻受害者，不冻他和镜头**：否。读起来像怪卡了，不像刀砍进去。
- **慢动作（0.3 倍速）代替冻结**：否。DNF 的手感是「停」，慢放会拖长整个连段。
- **给普攻加屏幕震动**：否。每一下都震会盖过技能的重击；震动留给 `shockwave`
  （`docs/adr/0025`）。
- **全局 `dt = 0`（时间也不走）**：否。配速线与连段窗口会丢帧，和录像比秒数就不准了。

## 验证

`npm test` **272/272**（这一片新增三条：命中停顿 3 帧、第三下击倒、挥砍中按键缓冲）。
`npm run test:browser` 键盘 / 触屏 / deep 冒烟**合跑绿**（见 `README.md` 第九十九切片）。

## 代价与未决

- **固定步长下停顿是整帧**：0.05 秒在 60fps 是 3 帧，不是精确的毫秒；要改就改
  `HIT_STOP` 的秒数，别在渲染里补。
- **浏览器机器人每刀会慢两三帧**：预算 360 秒已经留了余量；合跑若红先单跑复核
  （`CLAUDE.md` 那条「一次一核」）。
- ~~**技能自己的停顿、被打的停顿都没做**~~：第二版追记里补上了（见下）。
- **第三下是否该挑起来而不是打倒**：录像 30fps 分不清「倒下」和「小浮空」的起手；
  先按打倒做，实玩觉得该接空中连段再换 `launch`。

## 追记（2026-10-22 第二版）：技能与挨打

业主对第九十八/九十九切片说**「算可以了，继续」**之后，按 Q9 A 把技能这一半补上。

**一、技能每段命中按 `SKILL_HIT_STOP` 停 2–7 帧。**

表按招式重量给：上挑 0.05、崩山击 0.09、十字斩 0.04/0.04/0.06、
嗜魂封魔斩 0.06、崩山裂地斩 0.05/0.07/0.09、魔狱血刹·落 0.12（7 帧）。
多段招是数组，最后一段最重。**这些数和普攻那几个一样，是本作的**：30fps 的录像分不出
2–7 个 60fps 帧的停顿。技能自己的钟（`skillTimer`）在停顿里不动，所以实机时间会比
以前长一点 —— 这是打击停顿的本意，不是技能变慢。

**二、持续 tick 不停。**

嗜魂封魔斩的漩涡每 0.3 秒一跳、地面火每几帧一跳：每跳都停会把整招变成一串卡顿。
它们只走伤害与僵直；终结那一刀（`bloodyRave` 的 0.06）停。

**三、挨打：非致命不停，致命 6 帧。**

原计划挨打也停 3 帧，加在 `damagePlayer`。实测这 3 帧把浏览器机器人拖进和
胆小哥布林的换血循环（同一间房 30 秒挨 24 下，总伤害 122 → 224），所以**非致命
先不做**；致命那一下仍停 6 帧。他挨打原来的硬直、击退、受击帧都还在，只是世界
不再额外冻。霸体本来就不吃。

**四、停顿里按下的键不丢。**

世界停的那 3–7 帧里，`step` 仍然收输入：普攻记进 `attackBuffer`、技能记进
`skillBuffer`（0.4 秒，能放出来的第一帧兑现）、跳跃记进 `jumpBuffer`（0.12 秒）。
没有这一条，玩家和浏览器机器人在停顿里快速点下的技能/跳跃会被整个吞掉 ——
浏览器证明的键盘通路就是这么在领主房连红两次的（同一位置，排除抢核）。

**验证**：`npm test` **277/277**（新增五条：技能命中停 3 帧、致命一击停 6 帧且非致命
不停、停顿里的普攻/技能/跳跃输入都不丢）。浏览器键盘 + 触屏（`playability.mjs`）与
deep 冒烟（`deep-smoke.mjs`）**分别单跑绿**（一次一核）。
