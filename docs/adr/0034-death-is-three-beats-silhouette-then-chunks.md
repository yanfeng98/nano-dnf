# 死是三拍：**躺下 → 自己的白色剪影 → 炸成自己颜色的碎块**

**Status**: accepted（2026-10-11）。业主实玩之后先否掉了 `0033` 的读法，我把重量结果摆出来，
他又指了一次：**「怪物确实会躺着死，然后出现白色怪物轮廓，然后碎裂成血块（和怪物颜色一样）
散向四处」** —— 三个选项里他选了「按这个重做」。事后来看他是对的，我中间那一版读错了。

## 两次读错，错法不一样

**`0033`（上一片）** 把死写成：尸体躺 0.2s → **白烟盖住尸体**、烟散一起没 → 同时炸出碎块。
方向对了两样（躺、碎块），**错在白的那一团**：它不是"盖住尸体的烟"，是**这只怪自己变成的
白色剪影**。

**这一片的第一版（已废）** 更远：我把它读成"怪当场没 → 地上一片白云 → 什么都不留"，
理由是**只量了白色像素**。绿怪的碎块落在深绿草地上，按"接近纯白"去扫一个也扫不到 ——
于是**碎块整段被抹掉**了。业主一句「你视频中搞得不对」把它翻回来。

## 这一片量到的

业主的幽暗密林录像（1920×1080、30fps）：

| 拍子 | 量到的 |
| --- | --- |
| 躺下 | 业主的口径：「怪物确实会躺着死」。录像里 96.633 还站着、96.667 已经是白的，倒地那一拍短到 1 帧以内，**所以这条以他的话为准** |
| 白色剪影 | 白的那一团的包围盒 **276 × 114 px** —— 而那两只哥布林画上各是 **98 × 108**。**276×114 正好是它们自己站着的身量**，不是云的形状（这是"它是剪影不是烟"的铁证）。亮 **0.30 秒**：96.667 满 → 96.933 缩到 45% → 96.967 没了 |
| 碎块 | 白散的那一刻炸开，**按怪自己的皮肤色染**（T+4:50 那只量到十几块金黄的，飞出去 0.4 秒内四散、渐隐）。绿哥布林那一批飞的是绿的 —— 落在深绿草地上**几乎看不见**，这正是上一版漏掉它的原因 |
| 之后 | 什么都不留（录像里地上没有尸体、没有血泊） |

## 实现

1. **三拍都在 `enemy.dying` 一条时间线上**（`DEATH = { lie: 0.2, shape: 0.3, chunks: 1.6,
   chunkCount: 12, bossSmoke: 0.9 }`）：`dying > smokeLife()` 是躺着（画它自己）；
   `dying <= smokeLife()` 起 `enemy.silhouette = true`；数到 0 收尸并推一条 `deathburst`。
2. **剪影画的是这只怪自己**：`render.js` 的 `drawMonster` 在 `enemy.silhouette` 时换成
   `ghostSheet(image)`（整张怪图 source-atop 填一次白、缓存一份）—— 同一行、同一列、同一个
   落脚点，所以轮廓天然是它躺下那个形状，**不是另加的一层白**。
3. **碎块**用烘在 `forest.png` 里的 `chunk_<type>{0,1,2}`（十八块，三种形状 × 六种怪的色号），
   从**身上**起手（不是脚底）、放射出去、减速、坠地、最后半秒化掉。
4. **Boss 不炸**：录像里它只有那一片白（约 0.9 秒）、更大更久，一样不留东西。

## 补记：碎块的"厚度"（业主：「像落叶一样，不如视频中块更厚重」）

第三拍交出去之后业主又报了一条，量完发现是**三件事叠在一起**，三件都改：

1. **形状挑错了。** 烘出来的三张（`chunk_<type>{0,1,2}`，22×21 / 34×25 / 40×25）里，
   后两张是**带长须的"摊开"形状** —— 摊在空中就是叶子。现在只用**第一张那坨圆的**
   （22×21），放大到 0.7–1.3。
2. **动得太飘。** 原来初速小（±340）、重力小（400）、活 1.6 秒，是"慢慢飘下来"。
   录像里那些块 0.033 秒走约 65px（1080p）—— 几百 px/s，而且 290.167 出现、
   290.233 就没了（**0.1–0.2 秒**）。现在是**放射**（每块一个角度一个初速，绕尸体
   甩出去）+ 重力 900 + 活 **0.5 秒**；同一具尸体每次都甩成同一副样子（角度速度都由
   `seed` + 序号定死）。
3. **没有厚度。** 那些块是**实心带暗边**的：现在同一块先往右下压一个暗的当底
   （`chunkShadowSheet`，整张森林图 source-atop 压黑 50%、缓存一份），再把本来的
   那块盖上去 —— 底下那层就成了它的厚度和暗边。

## 补记二：碎块要**碎**（业主：「不如视频不规则……要一摸一样」）

补记一交出去之后业主又看了一次，这次比的是"碎"：我们那几块**又大又圆又整齐**
（一个圆形状放大到 0.7–1.3 = 15–27 世界像素），录像里那些是**小碎片**。
拿同一把尺把 T+4:50 那次的块全部量了一遍（1080p → 世界像素，÷2）：

| | 录像 | 我们（补记一之后） |
| --- | --- | --- |
| 块数 | **十来块**（量到 12–14） | 12 |
| 每块大小 | **4–17 世界像素**，多数 10–14；不少是细长的片（11.5×4.5、14×6、4×14） | 15–27，全是同一个圆形状 |
| 形状 | 不规则的碎片，横竖比都不一样 | 一种形状重复 12 次 |

所以：**三张形状轮着用**，而且**每块按目标宽度（6–17 世界像素）反推缩放**
（`scale = target / rect[2]`）—— 形状本身多大都不影响它落在屏幕上的大小；暗边也跟着
缩（`target * 0.14`，碎片小，2.5px 的边会把小块糊没）。块数 14。

**这一条只能对到"大小、数量、形状的参差"为止**：我们那三张形状出自客户端的
`sprite/common/hiteffect/splashbloodlarge.img`，是当时烘进来的；要换更锐的碎片形状得
回客户端重烘（这台机器上没有客户端 —— 等业主那份下了再说）。对照图见
`assets/dnf_src/dungeon-clips/mirkwood/sheets/chunks-compare3.png`。

## 补记三：飞散的距离（业主：「最后散开的距离太远了」）

上一版把速度加到 300–640 px/s、活 0.5 秒 —— 最远甩出 **300 世界像素**，等于半个房间。
量录像：那些块的速度约 **200 px/s**、活 **0.3 秒**上下，**最远飞 60–70 世界像素**
（一次击杀的整个炸开到散尽，也就两三个怪身位那么大一块地方）。
所以收成 **110–260 px/s、活 0.45 秒** —— 最远约 110，多数落在 60–80。

## 后果与教训

- `0033` 的"烟"这个读法作废；`0033` 的躺与碎块两样回来，并且这次量清楚了它们的**顺序**。
- **教训（两次同源）**：`0033` 是拿一句口述当一帧用；这一版是**拿一种颜色当全部颜色用** ——
  只扫白色，于是把同色的碎块当成不存在。**量一件东西之前先问"它可能是什么颜色/形状"，
  别用上一拍的答案去套下一拍。**
- 抓帧：`tests/browser/capture-death.mjs`（接管页面的 rAF 时钟、一格一格走，`KILL_AT` 定
  在哪一格杀怪）。对照图在 `assets/dnf_src/dungeon-clips/mirkwood/sheets/`（gitignored）。

## 追记（2026-10-18）：Boss 也炸，先光线、再魂柱与大血块

业主复看两次：「死亡特效按照参考视频做」「血块和特效还是与参考视频存在差异」。
参考录像的时间线是：

- 328.0–328.5s：**数条白/红细光束**从它身上甩出，外加一道金色横光；
- 328.5s：白色剪影 + 目标框红叉；
- 329.5s：白剪影散掉，**一根窄而高的蓝紫魂柱**升起，里面翻着**大块粉肉**；
- 330s：魂柱淡去，大血块散落/下坠，还有 74G 的金币掉落。

所以 `0034` 原来那条「Boss 不炸」**作废**：

- 领主一 `dead` 先推一条独立的 `bossrays`（0.7 秒，9 条红晕白芯光束 + 金色横光）；
- 白剪影照旧（更大更久）；
- 之后和杂兵一样走 `deathburst`，用 `chunk_boss*`，但 **Boss 那一档的碎块目标宽度
  是 36–60 世界像素**（杂兵仍 6–17），压一层**粉肉色**（`chunkPinkSheet`），
  活 `DEATH.bossChunks = 0.9` 秒；
- 渲染时碎块底下画的是**蓝紫魂柱**（`drawBossSoul`）：青蓝渐变柱身、四道粗漩涡带、
  细环与碎光点，不是一圈摊平的径向辉光；
- 目标框的红叉改成**常亮**（参考 328.5–329.0s 没有闪），带黑色描边；领主一死，
  条里那条橙色 `ALERT!` 也不再画，整条是黑的；
- `victoryDelay` 用 `DEATH.bossChunks`，让光线/剪影/魂柱/血块都演完再进胜利页。

## 追记二（2026-10-19）：魂柱是误读；白团有黑边，大碎块落地留到过关

业主复看：「领主死的特效还是不对」。这次按 1920×1080 原尺寸逐帧重对（328.0–332.5s），
上一段追记里至少有三处读错：

| | 参考（这次量的） | 上一版 |
| --- | --- | --- |
| 白色剪影 | **实心白 + 黑描边**，里面没有灰细节；哥布林的白团（96.667s）也一样 | 保留了原图的灰边/内部层次，没有黑边 |
| 魂光 | 白剪影散掉后，在它站的那一点亮一颗 **蓝白球**，约 **0.2–0.3 秒**（329.3–329.5s） | 一根 **0.9 秒**的蓝紫高柱 |
| Boss 碎块 | **10–14 块大的棕红碎块**，有的先飞后落，**落地后留在原地直到过关画面**（329.5–332.5s，约 3 秒） | 8 块偏粉的小块，0.9 秒淡掉 |
| 光线 | 细的红白光线 + 金色横光，约 1–2 秒 | 0.7 秒、9 条偏粗偏亮的粉光 |
| 节奏 | 白团几乎立刻出现（没有可见的 0.2 秒躺下），死亡→过关约 **4.3 秒** | `0.2 + 0.9 + 0.9 + 0.35 = 2.35 秒` |

所以：

- 白色剪影改成**实心白 + 黑描边**（`ghostSheet` 要先二值化 alpha 再描边），Boss 和杂兵同一套；
- `drawBossSoul` 的"魂柱"作废，改成一颗**短命的蓝白球**；`DEATH.bossChunks` 延长到约 3 秒，
  Boss 碎块改成**棕红、10–14 块、落地保留**；
- `bossrays` 延长到约 1–2 秒，光线收细；金色横光保留；
- `victoryDelay` 按 4.3 秒重算，让碎块在过关画面前留得住。

**教训**：上一段追记拿 329.5s 的一帧当"柱"，又拿粉色的印象去染肉块 —— 还是
`0034` 那句老话，**别用上一拍的答案去套下一拍**。这次先把 328–332.5s 每 0.1 秒铺成对照表，
再量颜色与时长。

## 追记三（2026-10-19 实玩）：光线从玩家剑上出，碎块用 Boss 自己的 metacowpiece

业主实玩：「领主散光和血块不对」。重看参考后改了两处：

- **散光**：327.5–328.6s 的光束是在**玩家剑上**交汇的，金色横光横在他胸口；上一版从
  Boss 身上向四周炸，读成 Boss 自己发光。现在 `bossrays` 记下最后一击的
  `sourceX / sourceZ`，光束从那里出发；金色横光长度收到约 **140 世界像素**
  （参考那一道约 450 视频像素，折过来差不多）。
- **血块**：`chunk_boss*` 来自通用的 `splashbloodlarge.img`，是血花；参考里的碎块是
  **牛头自己的肉**。客户端 `sprite_monster_tau.NPK :: sprite/monster/tau/metacowpiece.img`
  就是那五块（一块大的棕红肉片 + 三块小的 + 一块更小的），烘成 `assets/bossdeath.png`
  （`assets/import_dnf_bossdeath.py`）。领主碎块改用它；杂兵仍用通用血花。

同一天业主再说「还是不对」之后，又收了两处：

- **光线从 9 条 360° 星芒收成 10 条斜向**：参考 328.0s 的亮线集中在约
  47°/56°/154°/167° 那几条斜线上（另有一道金色横光），竖直/水平方向没有；
  9 条铺满读起来像"发光球"，6 条又太稀，10 条斜向更接近参考的密度。金色横光
  加厚到约 17 世界像素。
- **特效期间不弹提示 / "Boss down!" / 通关横幅**：原来领主一倒下就推 `clearBanner`
  （「幽暗密林 通关！」）和 "Boss down!"，再加上教学提示「清完房间门口会亮」，
  三层字正好盖在光/魂球/血块上；业主说的「放光不对」有一半是它们挡的。现在
  `victoryDelay` 期间 `syncHints` 不选提示、`resolveRoom` 不再推通关横幅、领主
  也不再推 "Boss down!"（杂兵仍保留）；通关字样留给结算页。
- **碎块的底边对地**：`height` 是底边离地的高度，但画的是块的中心；之前
  `cy = floorY - height` 把中心放在落地线上，大块有一半埋进草里（领主的大肉片
  尤其明显）。现在 `cy = floorY - height - h/2`，落地后是**坐在**地上。
