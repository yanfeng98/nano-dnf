# 城镇按录像中的场景重建，保留既有系统

2026-10-28，业主在 grill 访谈中确认：以 `00002-幽暗密林深处.mp4` 中的蓝天、白色建筑与栏杆、
浅色石板道路为城镇重建目标，连同人物比例、道路纵深和构图一并复核。
放弃继续沿用现有 Grenselos 街屋拼接并局部调色的路线：录像确有城镇画面，旧 ADR-0064 的
「没有城镇录像」前提错误；客户端 Hendonmyre 素材中的山景和屋群已与录像对应。

既有任务、商店、背包、仓库等功能和入口保留，融入重建后的场景；录像未覆盖的窗口使用客户端素材。
这项决定会带来场景素材、摆位和交互入口的重新组织；它不表示移动参数、全部素材和入口布局已定案，
也不表示已实现或验收。后续访谈与证据见 `../town-reference-review.md`。

随后确认：城镇只步行；人物比例、横向速度和步频依据录像测量，录像未覆盖的纵深、斜向与镜头参数
通过可实玩版本校准。城镇与副本的共享 HUD 一起修正，保留既有两排技能槽，检查满值、半值、零值。

最终一轮确认保留 NPC 职能与步行到城门的选关流程，将入口放在道路内且避免交互范围冲突。
业主已授权实施，自动检查与同尺寸对照之后仍须实玩确认，不能用检查通过替代体验验收。

2026-11-05，第十九批：重测V2 1.467–2.233s的完整八姿势步行片段。
每个姿势保持三帧（原片30fps），支持现有10fps；固定原生根的横向轨迹拟合约223px/s，
维持220px/s而不把短片段估计当精确常数。旧打包以每帧最低身体像素的脚尖横向居中，
脚尖本身摆动导致身体额外左右跳；固定根轨迹拟合RMS约1.88px，脚尖轨迹约8.03px。

城镇绘制将旧图集中每帧的原生(232,333)恢复到同一逻辑坐标，站立与步行共同处理，
再按朝向镜像；不改历史图集与副本动作的既有打包路径。补偿表由客户端原件和打包公式
独立测得，重建图集或改变打包公式后须重跑`scripts/measure-town-walk.py`复核。
不再用旧“140px/s、每步56px”的步幅论证代替录像证据。

仍只有一个城镇向左完整循环；服装、发型、武器待机外观、脚圈、精确人物比例和初始站位仍有差异。
此证据不支持修改纵深、斜向速度和镜头缓动。逐帧对照与实际浏览器坐标见总审计第十九批，待实玩验收。

2026-11-05，第二十批：V1首次城镇行走提供了纵向速度证据，替换原来没有录像依据的0.56。
12.2–12.5s与13.0–13.2s两段中，建筑水平位移及人物名字x均稳定；名字y线性拟合为
112.73与116.79px/s，残差约0.94/0.80px。同片11.5–12.0s建筑水平位移约227.12px/s，
人物名字x固定，得到纵横比约0.496/0.514。因此城镇纵向屏幕速度取横向的0.50，横向220不变。
这是一档有录像支持的近似校准，不把短片段、名字随动作的微小摆动当成原客户端精确常数。

撤销此前“纵向速度没有录像样本”的前提，保留斜向输入归一、道路范围、镜头缓动的待核状态；
此数据不能证明斜向输入规则，也不改副本depthSpeedRatio。V1约12.73–12.80s有城镇换区域，
脚底从前景/HUD后方出屏后在另一区域上缘出现，不能把跳变拟合成垂直走速或镜头缓动。
测量脚本与两个短区间逐帧证据见总审计第二十批。键盘回归先复现0.56超出录像估计范围，
改为0.50后通过，仍待实玩验收。

2026-11-05，第二十一批：替换没有录像依据的cameraRate=8持续缓动。
V1左移轨迹与稍后右移轨迹中，同一名字模板的屏幕中心分别约302/414px，相隔112px；
水平停止、只作纵向移动时，名字x与建筑x均保持稳定。后段另有名字横移而建筑不动的区间。
这些证据更支持中央活动区，而不是人物停止后镜头还追向正中央。

中央活动区半宽取56px，沿用720px视口的中心360；角色越过活动区边缘才平移镜头，
停止或在活动区内移动时保持镜头位置，并钳制到场景左右两端。撤销此前按指数cameraRate=8
追向中心的方案。调试定位入口仍可把人物放在屏幕中心，随后用同一活动区规则移动。

名字模板裁片中心不是角色原生根，故只用左右位置之差定半宽，不把拟合中心358px直接
当作新视口中心。三种模型在同一批轨迹上拟合：直接居中RMS56.20px，rate=8缓动39.49px，
活动区0.45px。这是拟合比较，不是独立样本上的精度保证，也不声称已还原全部隐藏镜头规则。
斜向输入归一和城镇区域连接继续待核；不改副本镜头。证据及真实键盘回归见总审计第二十一批。

2026-11-06，第二十二批：撤销城镇斜向输入归一。
V1同一连续区域18.4–18.633s单独纵向约110.36px/s；18.9–19.233s单独横向约222.14px/s。
18.667–18.867s同时产生横纵位移，扣除建筑测得的镜头平移后，约221.65/103.93px/s，
分别为单轴的0.998/0.942；缩到中间五帧的拟合为226.06/111.00，即1.018/1.006。
虽然斜向段短、名字跟踪带有像素误差，两种取窗都明显不支持两轴统一乘sqrt(1/2)。

城镇左右与纵深分别保持各自单轴速度，取消原来暂定的欧氏输入归一；不改横向220、纵横比0.50，
不把此片段当作副本移动或碰撞规则的证明。片段、误差与实际四向键盘回归见第二十二批总审计，待实玩验收。
