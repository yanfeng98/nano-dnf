# **每一件有它自己的大小** —— 怪有 `height`，布景原来没有

**Status**: accepted（2026-10-15）。业主答 **「全部按照推荐」**（上一轮我推荐的是：先把样本量够再定）。

## 先纠正一条我自己量错的

前两轮我报过「**本作的怪偏大 1.2-1.6 倍**」（哥布林 0.90 身位 对录像的 0.57-0.75）。
**那是错的**，错在量的是**素材**（`monsters.png` 里那一行 ink 的高度），不是**画出来的**。

渲染那边一直是这样（`drawMonster`）：

    var scale = enemy.height / MONSTER.stand[type];

也就是**怪表里那个高度既是美术、也是判定**，sheet 只是素材、按它缩。按那个数一算：
哥布林 **0.63 身位**、投掷哥布林 0.65、牛头巨兽 2.39 —— 哥布林**本来就落在录像的
0.57-0.75 里**。所以怪这一半是对的，**不用动**。

## 真正差的是布景

**布景没有那个数**：`drawScenePiece` 按**烘出来那张图的像素数**画，1 画布像素 = 1 世界像素。
而录像里**每一件是各自一个倍率**（客户端拿动画数据缩放每一件，那份数据在加密的
`Script.pvf` 里）。量出来那几个倍率是：

| | 录像里的倍率 |
| --- | --- |
| 木桶 | **1.83** 视频px / 画px |
| 哥布林 | 2.0-2.6 |
| 石拱门 | **2.52** |
| 牛头巨兽 | **3.38** |
| 脚下那颗椭圆 | **1.60** |

本作一律用 **3.155**（= 265 ÷ 84，身位换算那一条）。**所以偏大的都是那些倍率比 3.155 低的**，
而**没有任何一个统一倍数能把它们一起修好** —— 这也正是上一轮我说"不再是同一个比例"的原因，
现在有了它自己的解释。

**独立复核**：用**他脚下那颗椭圆**当尺子（它和主人的姿势无关，两帧里都在），
量同一帧里的木桶与牛头巨兽，得到"木桶偏大 1.67 倍、牛头巨兽 1.12 倍"——
和上表反推的 1.72 / 0.93 对得上。

## 决定

**一、布景也给它一个"画多大"，机制和怪的一模一样。**

`Core.PROP_SCALE`（一件一个倍率，没有的就 1）+ `Core.propScale(piece)`；
`drawScenePiece` / `drawScenePieceBox` 按它缩，**底边仍是落点**（缩了还站在那儿）。

**二、盒子跟着美术一起缩**（`propBox` 里乘同一个数）。

这是仓库里定过的规矩（`docs/adr/0032` / `0014`）：美术和判定必须是同一个数，
不然会出现"看着能走、结果被挡住"。

**三、只写量得到的。** 这一片写了两件：

| 件 | 倍率 | 依据 |
| --- | --- | --- |
| `barrel` | **0.74** | 录像 132-160 视频px 宽、182 高（两个深度各一个样本），本作 63x78 |
| `gate` / `gateUp` / `gateDown` / `door*` | **0.80** | 侧门录像 330 视频px 宽，本作 131 —— **上/下门没单独量过**，按同族推 |

**没量到的一律 1**：猜一个比留着不动更糟，它会把一件本来对的也缩坏。
木桶缩完 **0.69 身位高**，录像量的也是 **0.69** ✓。

## 追记（2026-10-15）：三条未决逐条办

业主把下面三条原样贴回来、说了「继续」，于是逐条办了。

### 一、牛头巨兽：201 → **168**，宽度与重踏半径跟着改

量准了：录像里它**站着**是 **355 x 530 视频px**（t=300 那一帧），而 265 视频px = 1 身位，
所以 **2.00 身位高**；本作画出来是 **2.39** —— 偏大 **1.20 倍**。
`height: 201 → 168`、`width: 172 → 138`（渲染按 `height / stand` 缩那张 sheet，所以两轴一起缩），
跟着改的是那一记地面重踏：`slam.radius 208 → 191` —— 那一圈是"盘子的边比身体半宽再远 105"
（`docs/adr/0036`），半宽从 (172+34)/2 = 103 变成 (138+34)/2 = 86，**那 105 是量出来的、不变**。

改完高度**正好 2.00 身位** ✓。宽度 1.64 对录像的 1.34 —— **宽高比仍对不上**（见下）。

### 二、布景那一大批：**开了个头，量到的是石柱**

t=150 那一帧站着**三根石柱**，边上就是他和三只木桶 —— 干净样本。取最左那一根：
**80 x 280 视频px = 0.30 x 1.06 身位**（顶上和脚下都看得见，脚底下就是草地）。
本作烘出来的 `pillar` 是 **44 x 111**；而且我把它和录像那一根并排看过，**是同一件**
（细长的石柱、爬着青苔）。

于是发现**两轴的倍率可以不一样**：这一件客户端**竖着拉长**了 —— 横向 1.82 倍、纵向 2.52 倍。
所以那张表**改成允许两个数**（`[横向, 纵向]`，一个数的意思就是两轴同一个）：

    pillar: [0.58, 0.80]

改完是 **0.30 x 1.06 身位 —— 和录像一模一样**。

**同一个毛病在牛头巨兽身上也有**：本作那张画的宽高比 0.82、录像里是 0.67 ——
**本作的东西普遍偏"胖"**。这一片先记着，没有逐件去量。

### 三、按深度缩放：**只有不挡人的那一档做了**

量出来的（**同一帧里**两只木桶）：靠前那只 **160 视频px**、靠里那只 **132** ——
**1.21 倍/整条带子**。

实现上只给**贴花**用（`DEPTH_SIZE = 0.18`，靠里的缩到 0.82）：贴花**不占身位、不进判定**，
缩了不用改任何一条判定。**实心件与怪一律不缩** —— 它们缩了判定就得跟着缩，而 `z` 要穿进
`blockProps` / `routeStep` / `swingProps` / `props` 布点**五个地方**；为前后 ±10% 去动
"美术与判定必须是同一个数"这条踩过坑才有的规矩（`docs/adr/0014` / `0032`），不值。

## 追记二（2026-10-15）：树干那一批也量了

「继续做」之后接着量。**只量到树**，但那一批是画面上最大的一坨。

**三棵直树干**（直 / 弯 / 长苔）。录像里那棵的**上段**是 **190 视频px = 0.72 身位**
（t=200 那一帧，树干两侧都看得清），而本作三棵的上段是 **1.40 / 0.82 / 0.93 身位** ——
平均偏大 **1.45 倍**，最粗那棵偏大 **1.95 倍**。

倍率取**三棵的平均 0.70**，**不是逐棵的**：录像里只看得见**一棵**，
而三棵都是直的、都长苔，认不出它是谁。逐棵要量得先认出它是哪一棵。

**只有横向** —— 树是**跑出画面顶**的（录像和本作都跑出去），**高度量不到**，
所以纵向留 1、等于把树画细。客户端自己就是两轴分开缩的（石柱那一件量过），
所以"只缩一个轴"不是歪门邪道。

缩完上段宽度：直 0.98 / 弯 0.57 / 长苔 0.65 身位，录像那一棵是 0.72 —— 落在旁边了。

## 追记三（2026-10-15）：阔叶树量到了，**高草还换了一件**

再量两样，**其中一样不是"大小"的问题，是拿错了美术**。

### 阔叶树

t=88 那一帧正中那棵：树冠左右、树顶、根脚**四处都看得见**。量到
**260 x 440 视频px = 0.98 x 1.66 身位**；本作烘的 `treeLeafy` 是 **153 x 203** ——
横向偏大 **1.86 倍**、纵向 **1.46 倍**。**又是"偏胖"**（本作那张画的宽高比 0.75、录像 0.59）。
`treeLeafy: [0.54, 0.69]` —— 改完 **0.98 x 1.67 身位**，和录像一样。

### 高草：**不是大小量错了，是那一件根本不对**

录像里的高草是**细高的一撮竖叶**（95 x 170 视频px，比宽高）；而本作 `SCATTER.tall` 用的是
`02obj201` —— **宽而扁**的一丛（127 x 66）。**形状正相反**，所以它根本不是同一件东西，
"缩多少"这个问题也就不成立。

客户端给幽暗密林**专门准备**的那一丛在**可破坏物**那个包里：
`sprite_map_breakableobject.NPK :: sprite/map/breakableobject/grass1.img`（39 x 87，八帧）、
`grass2.img`（17 x 76）。烘出来一看，**逐叶和录像那撮对得上**。

所以这一条改的是**出处**（`assets/import_dnf_scene.py` 里 `grass` 那一行换成那件），
不是倍率；换完按新尺寸重新量，`grass: [0.77, 0.62]` —— 改完 **0.36 x 0.64 身位**，
录像量的也是 **0.36 x 0.64**。

（这也解释了那条"**宽高比普遍偏胖**"：其中至少有一件不是胖，是**别的草**。）

## 代价与未决

- **主门以外的布景还没量**：树干、石头、草、灌木那一大批仍是 1。它们是画面上**最大的一坨**，
  真要量得逐个在录像里找干净样本 —— 这一片只开了个头。
- **牛头巨兽偏大 1.14 倍**（本作 2.39 身位，录像 2.09）：它改起来是一个数
  （`ENEMY_TYPES.boss.height` 201 → 176），但**它同时也是判定**，动它等于动 Boss 的手长。
  **没动**，记在这儿。
- **录像还按深度缩放**（近的桶 160 视频px、远的 132 —— 约 1.2 倍/整条带子），
  本作是平的。比"每件一个倍率"小一个量级，**没做**。
- **演示与测试的 bot 现在会砸桶**：挨在一起的几只桶绕起来比砸起来难（人是这么打的）。
