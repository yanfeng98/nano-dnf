# 出的这一招会带着他走：十字斩的位移在**人**身上，不在特效上

## Status

accepted（2026-09-28）。部分**推翻 `0007`**：那一条说「十字不再飞出」，对**第三拍**是错的。

## 决定

1. **`SKILLS` 多三个字段，说的是一招把他往哪带**：`advance`（px）、`advanceAt`（整招进度里的起飞点）、
   `advanceRamp`（这一步本身要走多久）、`advanceBack`（收招从哪一刻开始往回走）。
   位置由 `advanceAhead(skill, elapsed)` 从进度**直接算出来**，不走 `vx`：rooted 的阻尼会把
   0.06s 的一步抹成一条长滑行，墙和怪也会在中间把它拆开。收招结束时**精确回到起手那一点**
   （`skillTimer === 0` 那一帧补一次 `player.x = castOriginX`；最后一帧到不了进度 1，
   不然每一次施放都会净赚两个像素）。
   被打断的施放**不回位** —— 留在这一步已经走到的地方，那才是"被打断"的意思。
2. **`castOriginX`**：起手那一帧记下他站在哪。位移从它算，特效也从它画。
3. **`draw.anchor: "cast"`**（`src/render.js` 的 `drawEffectRow`）：这一行的特效**钉在起手原点**上，
   不跟着实时 `caster.x` 走。否则他一往前迈，整个十字跟着他一起挪，"穿过十字"就永远演不出来。
4. **`hitAt`**：一招可以自己点名三刀落在哪（整招的进度分数），不再只能把判定均匀摊在 active 窗口上。
   十字斩的三刀是 0.206 / 0.324 / 0.647，均匀摊不出来。
5. **`shot` + `spawnShot`/`updateShots`**：一招的某一段判定可以**离开他**，变成一条会走的盒。
   它有自己的钟、自己的速度、和一张"已经穿过的身体"的名单（每个只挨一次）。
   状态在 `state.shots`，与 `state.projectiles`（怪的，反向）分开。
6. **烘焙的 stage 多 `travel` / `grow`**：一段里的位移与缩放**按列线性插值**。
   一层不必拆成二十段去演"往前飞 + 缩小"。

## 为什么

### 那 19 轮到底卡在哪

`02_十字斩.mp4` 里最大的那次位移，是**他本人**。把他两只靴子在参考的**地面带**上逐帧抠出来
（`y 695..760`，亮而非特效色的像素）：

| 帧 | 靴心 x |
| --- | --- |
| `#18–#21` 站姿 | 762 |
| `#33–#37` 十成形 | 762–764 |
| `#39–#43` 十钉住 | 778–781 |
| `#44–#55` 第三刀 | **660** |
| `#56+` 站姿 | 761 |

`#43 → #44` 这一跳是 **118 参考px = 45.5 客户端px = 0.54 身位**，落在**第三刀**那一帧，然后一直停到收招。
而同一时间里「十」的墨框钉死在 `x 554–727` —— **他穿过了自己刻出来的那个十字**。

这一行之前是把特效**挂在一个不动的他身上**画的（`drawEffectRow` 每帧读 `caster.x`），
所以"他本人往前走"这件事从来没进过模型。前面每一轮都在解**特效相对他的落点**，
那些数是对的 —— 只是整幅画少了唯一的大位移。这也解释了为什么业主两次说「参考的往前移了」
都被量成「钉死」：**钉死的是十，动的是人。**

### 为什么位移要写在技能表里、而不是烘进美术

`0007` 的「八级飞出」（每级各写一个 `offset` 和一个 `scale`）就是把它烘进美术的做法：
业主说「不那么丝滑」，两轮后自己推翻了。位移是**玩法**（他走到哪，判定就在哪，怪就打在哪），
所以它属于 `SKILLS`；美术只画它。

同理，第三拍那团血气的**飞行与收缩**属于烘焙的 `travel`/`grow` —— 那是**画**在走，
而它的判定由 `shot` 给出，两边读同一组数（`ahead` 66、`travel` 49.5……），
因为**要他看到的东西才是打到他的东西**。

## 后果与代价

- **十字斩不再全程 `定身`**。它的朝向仍然锁住、输入仍然被拒，但它会带着他走。
  `CONTEXT.md` 的「定身」条目加了这一条例外。代价是真的会踩进地形危害 —— 净位移为零，跑不了图。
- **被打断时他留在半路**，45.5px。这是普通动作游戏的行为，但确实是 `0007` 时代没有的状态。
- `duration` 1.07 → **1.1333**（参考是 `#22–#55` 共 34 帧 @30fps，不是 32）。
  行也相应从 32 格变 **34 格**，于是**列号 = 参考帧号 − 22**，烘焙里每一段都能写成 `ref(44)`
  再对着片子读（见 `ref()` 的 docstring 与 `0008` 补记三）。
- **顺带修掉一个潜伏的 bug**：`enemy.bleed` 从来没存过 `interval`，于是 tick 里
  `timer += undefined` → `NaN`，「每秒 4、持续 3 秒」的出血**只跳了一次**就躺到过期。
  三刀改点之后出血测试的时间窗变了才发现。现在一次施放跳三次。
- **第三拍那一层换了素材，理由是一次方法上的翻案。** 它原来是 `gorecross_3cross.img` f1，
  选它的依据是「131x141 与参考量到的 148x138 几乎一比一」—— **那是包围盒的一比一**，
  而这一层是一根**斜跨整个方框的细丝**：框被它撑到 120x128，于是前二十轮每一次框对照都过，
  屏幕上一直是「一条红丝带」。把两边都**裁到自己的框、缩到同一尺寸**再比 IoU，并拿
  **业主认过的那一拍（十）当对照**。扫完 175 个包挑出
  **`_atgorecross/shoot.img`（十字斩自己打出去的那一件）**：它读起来是参考那只**实心的翅膀**
  而不是一条丝带，而且它是**这个技能自己的**东西。扫描落库成 `assets/match_effect_shape.py`。

  **这一条的教训比结论值钱，而且这一片并没有解决它。** 整行对参考的 IoU 只从 **0.218 涨到 0.291**，
  对照是 **0.385-0.449** —— **方向对了，没到位**：它现在是"一片实心的翅膀"，还不是参考那一只。
  还有一版把自己骗了：把「换对了」写成「scale+offset 搜索里 0.46 对 0.42」，而那两个数
  **来自两种不同的打分法** —— 同一种打分下对照是 **0.650**，**旧那一条细丝是 0.520，比换上去的还高**。
  细长的形状铺在什么靶上都得分，这正是它活了二十轮的原因。
  **一个 IoU 不算数；只有同一种打分法、对着一个已经认过的对照，才算数。**

- **每一层都要单独量一次"最远伸到他身后多少"。** 业主第二轮实玩说「剑气都到身后了」，
  按层量出来是起手横扫那三档（−107 client px，参考 −62）与白热竖弧第二档（整条在他背后）。
  整行看不出来的东西，逐层一眼就有 —— 量法与表在 `assets/dnf_effect_picks.md` 第二十二节。
  **这一条的方法教训**：`mirror_layer` 管的是"这一层摆在他身前还是身后"，它管不了
  "这一层自己画得有多宽、往哪边铺"，而后者会把一件摆在身前的效果**铺到身后去**。

## 没做的、留给下一片的

- **他往前那一步的"根位移"在参考里可能是动画自带的**：参考 `#55 → #56` 是在一帧里切回 761 的，
  不是走回去的。我们的做法（真的改世界坐标 + 收招走回来）在玩法上更保守（净位移为零），
  但和参考的实现路径不是一回事。理由与业主的口径见上文与 README。
- 第一/第二拍的金弧落点仍是 `0011` 补记三留下的未解决项（参考 `身前 −0.78..+0.78`），
  这一片只重解了第三拍。
