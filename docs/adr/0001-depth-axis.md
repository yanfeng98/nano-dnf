# 深度轴：地面从一条线变成一块带

## Status

accepted（2026-09-25）。**推翻 `README.md` 第 54 切片**"加 Y 轴……那是重做游戏"的判断。

## 决定

`ARENA.groundY` 从**一条线**升级为**一块带**：新增一个与高度正交的地面轴 `z`（深度），
`y` 的物理语义一个字不改（重力、跳跃、浮空、落点全部照旧）。人、怪、判定从此站在这块带上不同的
深度上，"走位"成为可用手段。真正的 DNF 有 X/Y 两个地面轴——`z` 就是我们缺的那个。

第 54 切片说"那是重做游戏"，**这句话是对的**：爆炸半径（碰撞、所有技能的判定盒、所有怪的 AI、
房间、相机）一条不少。推翻的不是这个判断，而是"所以不做"，改成分五片增量交付。

## 决定的一整套（每条都可单独反驳）

1. **`z` 是新增字段，不重定义 `y`。** `y` 现在同时是屏幕纵向、物理高度和地面接触点
   （`bodyBox.bottom = entity.y`，`core.js:1204`），被 160 个测试钉住；换掉它是纯亏。
   深度作为正交的第二个地面轴加进来，是加法。
2. **`z = 0` 就是今天的地面线**，也是地面带的**前缘**。凡是还没吃到深度的地方一律 `z = 0`。
   这条是兼容性不变量：**`z` 全为 0 时，输出必须与今天逐字相同，160 个测试必须原样通过。**
3. **投影只有一个常数 `0.22`**，原本硬编码在四处地面椭圆里（`drawHazards` 一处，`drawEffect` 的
   telegraph / shockwave / collapse 各一处）。第五处 `radius * 0.19` 是同一压扁的手调近似
   （0.88 × 0.22 ≈ 0.1936），不是另一个常数，所以没动它。这个数同时就是"深度→屏幕纵向"的斜率，
   等于一台 **12.7° 的极浅机位**。
4. **地面带住在屏幕 `[310, 430]`**，120px ≈ **0.77 个 Slayer 身高**（156px）。画布与热键栏都不动
   （地面线 430 到热键栏 444 之间只有 14px，向下没有空间）。
5. **带宽与边界写进每个房间**，不是全局常量。
6. **走位复用 `ArrowDown`/`ArrowUp`**（`held.down` 早已解析、从未被读取），撞边夹住不滑动，
   只按上下也播跑步动画，走位永不改 `facing`，`rooted` 期间与 `vx` 同样压制。
7. **判定统一成区间**：攻击方带一个深度区间 `[from, to]`，防守方是一个点。近战默认区间 =
   施法者深度 ± 0.3 身高（等价于点容差）；大蹦/崩山击给 ±40 的宽区间；`rageBurst` 走
   `hypot(dx, dz) <= radius`。**这一条与第 3 条互相钉死**：那个圆判定画出来正好就是被 0.22
   压扁的椭圆，判定与美术永远不用对表。
8. **贴地锚点：一个"落点"是八个数，不是一个坐标加一个朝向。** `ground: true` 的高度那一半切片 ①
   已经做掉了——它现在钉的是**施法者所站那一行的地面**，不是地面线。剩下的一半是深度：凡是"留给场地"
   的记录（`state.fields`）和场地上的记号（冲击波环、怪的攻击预警）都得把深度**烘进记录**，人被打飞、
   被击退、或走到别处，它都不动。
   **修正（切片 ③ 建时）**：这一条原本还写着把锚点升级成深度**区间**（`{from, to}`）。区间只有切片 ④
   的判定会读，在那之前就是死数据，所以这次只烘了**一个点**（记录里的 `z`），区间跟判定一起进 ④。

## Considered Options

- **重定义 `y` 为深度、另加 height 字段**——否。`y` 的物理已经写对（重力 2200、跳速 −760、
  per-skill `leapGravity`），160 个测试会同时失效，纯粹是亏。
- **第二个投影常数（例如 0.385）去凑一个"看起来更舒服"的带高**——否。得同时重烘 5 处地面椭圆，
  而且判定椭圆与美术椭圆会永久差一个系数，每改一个技能都要重新对表。
- **画布加高到 960×640，换取一条可朝镜头走的双向带**——**推迟，不是否决**。视觉上更像 DNF
  （带宽能到 1.6 身高），但代价是 canvas 与 `ARENA` 同改、背景三层重画、移动端适配、CI 资源清单、
  浏览器测试的坐标断言。它**与深度轴的逻辑正确性完全无关**，可以独立推进；先做浅带验证假设，
  读起来还是假再上。
- **深度只做表现、不参与判定**——否。那样走位只是贴图平移，会引出"剑从怪身上劈过去却掉血"
  这种**比现在更假**的观感。
- **把贴地美术按投影压扁成"地面贴片"**——否。地裂**那一行**里还站着两根火柱（近身的两根柱子与地裂
  同烘在 `mountainRift` 那一行，因为它们在人身前、得画在他后面），按 0.22 压扁会把那两根一起拍平。
  真正的做法是把那一行拆成"地面层"与"竖直层"两张、只压前一层，那是**重烘美术**的活，不是渲染的
  活。所以现在所有技能都是**广告牌**：钉在它该在的那一档深度上，形状不变——真 DNF 也是这么画的。
  这条不进渲染，进美术清单（见 README 的「下一步候选」）。
  **第 61 切片把地面单独烘出来看过之后补一句**：`outragebreak_floor.img` 那十一帧**全是**俯视画的
  地面（岩板、裂缝、环、亮网），里面**没有**竖直的火——所以"压不得"说的是**那一行**，不是这批图；
  而且它**画的时候就已经带透视**（那颗"椭圆"本来就是个摊平的圆），再按 0.22 压一次是**把透视算
  两遍**，那片 1.09 身位深的地会塌成 0.24。这与 `0002` 撤回的那次是同一个坑：**别从美术的椭圆里
  读出机位**。

## Consequences

**必须接受的代价：**

- **朝镜头走做不出来。** 地面带只能向屏幕里开，今天的地面线就是前缘。这是浅带的直接后果，不是疏忽。
- **背景要重画。** 墙现在从 120 铺到 430、地板从 430 起（`render.js:556-621`）；墙脚得抬到 310，
  5 条地板木纹（438..494）降级成前景，火把（硬编码 `y = 250`）跟着墙走。**这一片在切片 ①，不带
  任何玩法变化**，可以单独看"地板到底像不像一块地"。
- **后缘腾空会顶到屏幕上沿。** 站在后缘（脚在 310）放大蹦，250px（`leapUp −1500` /
  `leapGravity 4500`）会升到 `y = 60`；普通跳跃 131px 落在 179，无事。靠抓帧验收，不接受就回头改第 3 条。
- **走位速度必须在屏幕空间定**，因为"纵着走"要读起来和"横着走"一样快：z 速度 ≈ 0.75 × 265 ÷ 0.22
  ≈ 900 单位/秒，穿过整条带约 0.6 秒。

**不该被误解成"顺手"的几件事：**

- **地形危害是整条全深度条带，不是地面上的一个点。** Sunken Chapel 的设计意图是**计时**谜题
  （"the safe ground keeps moving"，`core.js:809`）；给它一个窄的深度区间，玩家往旁边挪一步就躲开了，
  谜题就没了。数据形状统一用深度区间，**现有两种危害的区间默认取满整个带**，行为与今天一致；
  以后想要"地平面上一块"的危害，给它一个窄区间即可。
- **飞行道具带着发射者的深度常量**，飞行中不变。它现存的每一行代码都不用动（死亡线仍是
  `y >= groundY`，因为 `y` 是纯高度）；只是命中判定多一项深度对齐。
- **掉落物绝不能新抽一次随机数。** 掉落位置走确定性 RNG 流（`core.js:1310-1320`），加一次取数
  就会打碎回放与掉落位置的测试。掉落的深度 = 掉落点的深度，**零次新取数**。
- **怪物在切片 ④ 会打深度判定，但不会走深度。** 它们追你的 x、不追你的 z——一个可测也可玩的
  中间态。怪的走位与容差同步留在切片 ⑤，因为容差的松紧只有玩家自己走起来才知道。
- **`↑` 会和路线图上的指令输入撞车。** 已在切片 ② 定案，见下。

## 切片 ② 的决定（2026-09-25）

建第二片时定了三件事，都记在这里，因为前两件改的是玩家看得见的东西：

1. **`↑`/`↓` 走位，跳跃只剩 `C` / `Space`。** 这比"和未来候选撞车"更要紧：`↑` 当时**已经是跳跃键**，
   而且写进了 README 的操作表。`W`/`S` 不能顶替——`KeyS` 是槽位 1（崩山击）、`KeyW` 是槽位 7——
   所以键盘上 `↑`/`↓` 是仅剩的两个空键，二选一只能留走位。DNF 自己就是这么分的。
   README 操作表、屏幕提示、帮助页三处跟着改了。
   另外，**浏览器端到端套件自己一直在用 `↑` 当跳跃键**（`KEY_FOR_ACTION.jump`）；不改它，
   键盘通路的跳跃会静默变成走进屏幕，而套件照样"通过"。已改为 `KeyC`。
   路线图上的「指令输入（`↑`+`X` 上挑）」没有被废掉：它按真 DNF 的办法实现——同帧按下＝指令、
   按住＝走位。这条留给实现它的那一片。
2. **触屏加了 2×2 四向块**：现有 `←`/`→`（22,418 / 120,418）原样不动，上方加 `↑`/`↓`
   （22,330 / 120,330），四键都是 86×86。触屏那条通路因此不欠账。
3. **attract 基准不需要重新固化。** 原判断是"输入多了 z 轴，演示回放会变"，但演示机器人从不按
   方向键，所以什么都没变——这条预测落空的方式正好是最有用的那种：**5040 帧的渲染轨迹逐帧不变**，
   成了第二片那次渲染重构（把手工画家顺序换成按深度排序）的证明。深度排序在全世界 `z = 0` 时
   是可证明的空操作，因为它对同深度的平局保留了原来的次序。

## 切片 ③ 补记（2026-09-25）

**它修的其实是一个真 bug，而且是抓帧抓出来的**：`state.fields` 的记录里只有 `x / y / facing`。
施法期间那几行是读施法者画的（深度正确），可一旦交给场地，`depthLift(undefined)` 就是 0 ——
**在 400 深处打出去的地裂，交接那一帧会自己掉回地面线**（低 88px）。抓帧对比：交接前一帧火在脚下，
交接后一帧整片掉到地板前缘。修完之后 `fieldZ=400`，余烬仍在他站的那一行。

有两处半，缺一不可：**记录**要收下深度（`spawnField` 现在收的是"施法者"而不是四个散参数——那个"落点"
本来就不该拆成 x/y/facing 三样而漏掉第四样），**交接处**也要把它递下去（`drawFields` 递给绘制函数的
是一个新造的对象，不是 field 记录本身，所以那里也得带上 `z`）。只改一处，抓帧还是错的。

同一个 bug 的另外三处：技能自己的冲击波环（血之狂暴、银光落刃会画环；崩山击与大蹦 `arc: false`，
本来就不画）、怪的预警标记与 Boss 砸地的环。后两个今天看不到差别（还没有房间把怪放在深度上，那是 ⑤），
所以它们的测试是**先把怪放到 250 深度**再验——不然这几行会一路静默到 ⑤。

**没做的一件事**：把施法者那几层美术并进深度排序。那会把"怪画在裂缝之上"变成"怪画在裂缝之下"之类
同深度下的次序变化，属于画面决定，跟 ④ 的判定区间一起做更合适（那时它们都得有深度区间）。
现在这两趟的顺序原样保留。

## 切片 ④ 补记（2026-09-25）

**判定**。每个攻击现在带一个深度区间，每个身体是地板上的一个点：`inReachOf(z, at, reach)` 是唯一的
入口，`reach` 以 Slayer 身高计，缺省是一次挥砍的。近战 0.3 身高（47 z，约地面带的十分之一）；
小 Boss 的旋风 0.6（它扫的是**车道**，本来就不止一个身位）；大蹦与崩山击 0.75（**它们铺的是一块地**，
而这个数来自它们美术里那句谎——切片 54 把 12 根火舌错开 ±26 客户端 px 冒充"地平面上一块火"，
±26px 屏幕就是 ±118 z，于是判定和画面第一次对同一件事达成一致）。

两个形状上的决定：**半径类招式（怒气爆发、Boss 砸地）走 `hypot(dx, dz)`**——它们是地板上的一个圆盘，
x 与深度的量法必须一致（这就是"投影只有一个常数"那条决定在战斗里的样子）；**其余是盒子加深度区间**。
飞行道具带的是它自己那一档深度，与玩家的深度用 x 判定同样的余量比。

**这一步之后的战斗是什么样**：站在怪的那一行才能打到它，也才能被它打到。所以走位是防守也是代价——
挪开一步两边一起落空，不会出现"站到远处白打"的刷分位。测试逐条钉住了这一点（挥砍打空、怪的反击也
打空、旋风在纵深上比挥砍宽、地面招覆盖它画出来的那块、半径招是个圆盘）。

**为什么近战那个 0.3 留得很紧**（±10px，只有地面带的 17%）：一开始担心"玩家会一直对不齐而烦躁"。
把切片 ⑤ 想进去就通了——**怪会走到你那一行**，所以常见的交手是两边都已经对齐的；真正会落空的，是你
自己走开之后立刻挥的那一刀，而那一刀**本来就该落空**。再收紧没有意义，放宽则会把上面的旋风和地裂
挤近，而那两个数各有出处（车道；以及 ±26px 那句美术谎）。旋钮留在 `DEPTH_REACH.melee`。

**美术并进同一次排序**。原来画面是手写的画家算法，施法者那几层夹在身体的两半之间；现在房间里所有
会动的东西各带一个深度进同一条链，远的先画。只有两类不是"它站在哪"：施法者自己的行（**属于他**，
取他的深度 ± 一个间隔，靠后的行与靠前的行）与 field（**属于它被打开的那个点**，取那个点的深度 ±）。
身体与玩家同深度时仍然算"在他身后"（排序是稳定的，身体先入链）。

**这次画面确实变了，而且只有次序变**：5040 帧里 **168 帧**的调用序列不同，抽查任一帧，发出的
**1578 次 canvas 调用完全相同，只是次序不同**。变化是"怪站着的裂缝该压在它脚下还是盖在它身上"——
现在压在脚下（怪画在裂缝之上）。切片 ③ 把这件事单独留到这一片，就是因为它是一次画面决定，
需要跟判定区间一起被看。

## 切片 ⑤ 补记（2026-09-25）

**怪开始走第二条轴**，这一行是"纵深是战场还是藏身处"的分界：没有它，玩家可以站在每一只近战怪的隔壁行，
两边永远打不着，他可以一直站着。有它之后，"退到远处"不再是防守——**防守是趁对方已经起手时挪开一步**，
而那一步之所以有效，是因为怪比人慢：`depthSpeedFor` 对两边是同一个规则（屏幕系数 0.75 除以投影 0.22），
所以怪在深度上是玩家的 **0.24–0.36 倍速**，与它们在 x 上的相对速度**完全一样**（同一个 `speed` 乘同一个系数）。
纵深和横向一样可逃，这是构造出来的，不是调出来的。

**远程怪守住自己那一行**，这是让房间数据真的有分量的那一半：施法怪的子弹带的是它站的那一行
（切片 ① 就定死了），所以它走到玩家那一行毫无好处、坏处很大——**守住不动，玩家就得同时跨过 x 与深度
才能打到它，而全程它在开枪**。近战怪相反，它们会走到你那一行（上面那段）。这两条一起才让 spawn 深度
不只是开局 0.77 秒的布景。

这条决定的证据来自一次测试失败：把"施法怪守行"写进去之后，`kitingBot`（测试里那个只懂 x 的通关策略）
**通不了关了**——它走到怪跟前，然后一直对地板挥砍到超时。也就是说，不懂这一轴的策略现在真的打不过，
这比任何断言都更能说明这条轴是承重的。

**房间怎么表达深度**：`{type, x, depth}`，其中 `depth` 是**房间自己地板的一个比例**（0 是前缘、1 是后墙），
在 `startRoom` 里换算成 `z` 一次，之后一切只谈 `z`。理由很实际：同一个 `z = 200` 在礼拜堂是 37%、
在王座间是 73%——绝对值得看房间多深才知道它是什么意思。名字也不一样（`depth` 对 `z`），两种单位不会混。

**房间数据终于被用上**（决定 #5 说带宽属于房间，此前没有房间用）：

| | 屏幕高 | 纵深 | 以身高计 |
|---|---|---|---|
| 默认 | 120px | 545 z | 3.50 |
| 沉没礼拜堂（自称"更宽、更慢"） | 150px | 682 z | 4.37 |
| 哥布林王座（终局） | 60px | 273 z | 1.75 |

王座间是一条**窄台**：王的砸地是个圆盘，台子越窄它越咬人，剩下的答案只有那个一直都在的跳跃。
礼拜堂反过来给一块大地板。两个数各自只有一个，都是照房间自己原有的说法定的。
另外 **Broken Span 的施法怪开局站在 200 深度上**（44px）：远程怪在两个轴上都保持距离。
注意 spawn 深度只决定**开局那几秒**——之后是 AI 的事，它会自己走过来。

**两个机器人也学会了这一轴**：演示机器人与浏览器机器人都在接近目标时同时走 x 与深度，阈值取游戏自己的
`DEPTH_REACH.melee`（不是另拍一个数），走到该走的行才挥砍。不改它们的话，浏览器套件会在 Broken Span
原地对空气挥到超时——这本身就是"怪不再只活在 x 上"的证明。顺带修掉一个同源的旧毛病：
`separateEnemies` 原本只按 x 推挤，现在两行上的两只怪不会互相挤开（一个身位宽，和别处同一个读法）。

**引导**：远程怪守行之后，"打不着"成了玩家唯一的、也是最不透明的失败方式——他挥砍，什么都没有发生，
游戏一个字也不说。所以 `hints.js` 加了一条「站到怪那一行才打得到它」，触发条件是"他在挥砍而每一只怪
都不在他那一行"，阈值取 `DEPTH_REACH.melee`（提示与判定必须是同一个数，否则会出现"提示让你走过去、
而你已经站在那一行"）。`hints.js` 因此要拿 `Core`（它本来就排在 `core.js` 之后加载），但仍然无 DOM、
仍可单测。

**验证**：188 条测试 + 浏览器两条通路（含新增的"这一局它确实走进过屏幕"断言）。
**这一片是轨迹不再成立的地方**：①–④ 都能拿"没人走位时逐帧不变"当证据，因为演示里没人走位；
⑤ 之后演示自己会走位了（有房间把怪开在别的行上），于是第 377 帧起全程分歧——从那一帧往后
5040−377 = 4663 帧全部不同，一处分歧再不复原。这不是回归，是这一片本来要的效果；
此后这类改动要靠测试与抓帧，不能靠轨迹。
