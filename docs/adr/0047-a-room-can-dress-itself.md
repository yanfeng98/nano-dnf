# 一间房可以自己改撒景的件数，Boss 房的高草几乎为零

**Status**: accepted（2026-10-15）。业主说「继续」之后做的。

量自录像：**六间房不是一副样子**，量到差别最大的一档是**高草** ——
Boss 房（R6）**一屏 0–2 丛**，别的房间 0–5。

## 决定

`SCATTER` 的三档（矮草 / 粉花 / 高草）各自有一个默认件数，**一间房可以在自己的 spec 里
用 `scatter` 盖掉其中任意一档**（`beginRoom` 把它带进 `state.room`）。只有 Boss 房写了：

```js
scatter: { tall: 1 },
```

于是那一间撒 **2** 丛高草（1 丛是撒的 + 1 丛是人写的），别的房间仍是 8–9。
**布景总数那一档没动**（仍落在录像量到的 50–90 里）。

## 为什么只做这一档

- **它是量出来的**，而且量得干净（一屏里数得清的丛数）。
- **`SCATTER.solid` 那一档不能这么改**：立着的实心件**挡人**，而怪不会绕路
  （`docs/adr/0032`：`blockProps` 那一节写着「**没有人绕路**…所以摆布景的规矩是
  **别把它摆在小怪必经的直线上**」）。Boss 房要补的是"石头一屏 2–7 块"，那**不是
  改个数就行的活**，得先让怪会绕 —— 见未决。

## 代价与未决

- **Boss 房那地板**：录像里它是**另一种砖**、几乎纯黑。这一条**做不了**：
  02 套的 `tile00..03` 不是四种砖，是**地面带的四段**（224 宽、高度 203/233/233/235，
  上沿是斜的），拼起来才是那一条带子；本作拿 tile2→tile1→tile3 循环铺。
  要换砖得从别的套（00/01/03/04）里取，而那会**换掉整间房的地面**。
- **实心件密度（石头一屏 2–7 块）仍然没补**，卡在"怪不会绕路"上（见下）。
- **木桶也是实心的**：录像一间房 **5 只**（散在可走的走位带里），本作 0–3 只，
  卡的是同一条。
