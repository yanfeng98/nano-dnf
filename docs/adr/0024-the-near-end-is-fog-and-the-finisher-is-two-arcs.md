# 近端是一团雾，收尾是两道金弧：嗜魂封魔斩的两层，与"深度只抬一次"的锚

## Status

accepted（2026-10-05）。业主在 grill 上一句 **「都按照推荐，Q3连金叉一起重做」**：
Q2 选 A（照参考补上近端那团雾）、Q3 选 B（收尾的金叉一起重做）。
它**部分推翻了 §25 里「那三块各有主人」的收尾读法**：那一次只认了 `finish_dodge` /
`lslash-dodge` / `scrach` 三块，而参考的收尾里最大的一层（红爆）从来没进过烘。

## 决定

**一、一条骑在施法者身上的效果，锚点是他自己的脚，深度只抬一次。**

`drawBloodVortex` 曾经这么落地：

```js
ctx.translate(player.x, feetY(player) - Core.depthLift(player.z || 0));   // 旧
```

而 `feetY(body)` 自己就是 `body.y - Core.depthLift(body.z)`——**整团漩涡比他多抬了
`z × DEPTH.scale` 那一次**。实测：同一招、同一进度，z=0 时近端墨迹在他脚上
+0.65…+1.00 身位，z=400 时 +1.70…+2.04，差正好 1.048 身位 = `depthLift(400)/84`。
业主截图里他站在带子中段（多抬约 0.4 身位），那就是「高于手」的全部。

**这一条要留给下一个人的不是那行代码，是它的证据规矩：**

> **"这个效果在不在他身上"这种话，证据图必须在 `DEPTH≠0` 再拍一张。**
> 抓帧脚本 `tests/browser/capture-effect.mjs` 的 `DEPTH` 默认是 **0**——而 z=0 上
> 两次抬升正好抵消，美术真的贴着手。前四轮对照图全拍在唯一看不出问题的地方。

**二、漩涡的近端是一团雾，不是一根细环。**

参考里近端那团的像素**均值 88**、中远处那些环 **159**——细环再细也是全亮的，
只有低透明度的雾才会这么均匀地暗；94 帧（#059–#152）里它稳定地从**身前 0.36 身位**
起（p10–p90 = 0.30–0.41）、纵向 0.58–0.95，**罩在掌心上**（掌心 0.81）。
本作包 `sprite_character_swordman_effect_bloodyrave.NPK` 里 **`loop-dodge.img`**
（十二帧血云）一直没人用——就是它。烘成 `bloodyRaveMist` 行、活画在
`EFFECT.vortex.bloodyRave.mist`，`alpha 0.5` 就是照 88:159 定的。
**亮环从雾外面才开始**：从现在起，"近端"说的是雾，不是 `u = 1/13` 那一环。

**三、收尾（#162–#170）是"红爆 + 一道金叉"，而金叉是 `lslash-dodge`。**

认法是**模板匹配**，不是看着像：把客户端条目镜像后按白芯掩膜做尺度+平移搜索——
参考的 #164 / #166-168 / #169 对 `lslash-dodge` 的 f1 / f2 / f3 白芯 IoU **0.92 / 0.93 / 0.72**，
f0 是 #162 的起手闪、f4 是 #171 的尾。**三帧独立解出的尺度都是 ×1.8**，正好是这个视频自己的放大比
（800×600 的游戏窗口放到 1440×1080）——**即游戏拿包里的美术按客户端像素 1:1 画**，
所以本行的 scale = 客户端 scale × **0.68**（1 客户端px = 84/123.5 屏幕px），落点也照这条推。

两条跟着来的结论：

- **白芯不用另加一层**：它是 `lslash-dodge` 自己带的（勾上没有、长劈上有）。
  `scrach`（白闪）与 `finish_dodge`（白扇/细弧）都**不在这一下里**——后者与参考的白芯最佳 IoU 只有 0.05–0.44。
- **红是两层**：尖芒段（#162–#164）是 `finish_normal`（客户端里 ×0.92），#166 之后的主体是
  **`light.img`**（客户端里 ×0.43，质心身前 1.70 / 离地 0.77、2.06 × 1.84 身位）——
  我们原来只用它当 0.34 的小余晖。**金压在红上**（把金笔内缩后内部只有 0.6% 的像素落在红类里）。

**窗口**：`PICKS["bloodyRave"]` 的窗口只到客户端 x=360，`fit` 把裁切线放在 x≈271——
而 `lslash-dodge` 的叉尾伸到 x≈280：**右边一截从来没画出来过**。窗口加宽到 x=500，
`size` 571 → 720（= CELL / fit，1 客户端px 仍是 1 屏幕px，所以整行其余部分一个像素都没动）。

**四、吸满 3.13 秒时，由它自己收。**

`0023` 写的是「**不松手到 3.133s 自动收**」，代码却只认松手——按住不放那一趟，
收尾的伤害与美术**全都不出**（`hitTime` 在没有 release 时是 `Infinity`），而参考演的就是那趟：
它按满稳态、在 4.300s 劈出去。上限那一刻"松手"不花时间（尾巴正好剩 `tail` 秒），
只是把 `channelReleasedAt` 记上。

## 为什么

**近端那团用亮度而不是形状认出来，是这一轮唯一的新尺**：「细环画小一点」与「一团低透明度的云」
在小尺寸的包围盒上几乎一样，只有像素亮度分得开（88 对 159）。
`midY` 也是同一把尺顺下来的：沿长度十等分量的参考中线是**一条平的 0.81 身位**
（0.75–0.86，94 帧平均）——旧的 −73（0.87）高 5px，那 5px 就是"高"里除深度 bug 之外的那一点。

**收尾那一层红是"缺件"，不是"参数不对"**：旧烘的三块都在金色里找，参考里最大的一层
（红爆）在包里是 `finish_normal`，`normal` 与 `dodge` 是**两套板**而不是同一张图的两个色板——
这一条 §25 第一次倒包时没分开，于是那一层从来没被点过名。

## Considered Options

> **近端只把最近的环往手边收（不补雾）。** 否。参考的近端是量得到的一层实体；
> 把环收回来只是让一根细环更贴手，读起来还是"细环悬在手前面"。

> **收尾继续用"两笔交叉"的旧烘法（`lslash` + `scrach` + 旋转）。** 否。它给出的是一团亮橙球
> 与一梳离他 3 身位的笔；参考要的是两道**细**弧在红爆里交叉。

> **把白核（f0）整条撤掉。** 否——但第一版差点这么干：参考的爆点确实有一扇白光，
> 问题从来是它的**时长与尺寸**，不是它的存在。

## Consequences

- `assets/effects.png` 多一行（第 19 行 `bloodyRaveMist`），`EFFECT.extraRowCount` 8 → 9；
  烘焙脚本的 `EXTRA_ROWS` 与 `PICKS["bloodyRave"]` 的尾巴段重排（新的从/到按**尾巴自己的钟**：
  列 = 10 + 秒 ÷ 0.0548，分数 = 列 ÷ 23——旧值把进场的换算用在了尾巴上，整段金早了 0.17s）。
- `EFFECT.vortex.bloodyRave.midY` −73 → **−68**；新增 `mist`。
- `CLIPS["bloodyRave"]` 的帧表里第二个 176 → 175（176 是"手放下、剑拄地"的站立帧，
  落在 0.182–0.839 的**站桩拍**里，拍子的帧是循环播的——三秒长按有整整一秒不是施法姿势）。
- 测试钉两条：**漩涡的原点在任何深度都等于 `feetY`**（`Render.render` + 录制 ctx，z=0/220/400）；
  **站桩采样里不许出现与开场那一列相同的帧**（直接读 `assets/slayer.png` 的像素）。
- 收尾的**余晖**（`light.img`）加了 `alpha 0.55`：包里那盏光是实心红球，参考的余晖是软雾。
- 还没被业主看过的地方：金弧本身的粗细与亮度（参考的两道更亮、更粗），以及白核的尺寸。
