# HUD 照 00002 与客户端：6+6 技能槽、真实 MP、删掉本作附加 HUD

**Status**: accepted（2026-10-22）。**改写 `ADR-0041`（HUD 组织）与 `ADR-0060`
（领主头顶名字）；修改 `ADR-0040` 的触屏那一条（4:3 窗口本身仍有效）；
`ADR-0054` 的领主条尺寸仍有效，重排时照它。** 业主在 grill 上选的是：UI 也照录像重做、
录像里有的全加、本作附加 HUD 全删、字号严格 50%、删触屏、照 DNF 键位。

## 一、照录像的 HUD

`00002` 的游戏画面是 1440×1080；本作世界窗口 720×540，正好一半。**版式、组件位置、
血条长度、字号全部 ×0.5**，不为了可读性单独放大（业主选 B）。

- **左上**：目标条（头像、`人型/野兽`、`Lv{n} 名字`、血条），领主时换成整条领主条。
- **右上**：方形地图窗口，深处是 5×4/18 格；领主房红牛头从第一帧露出。
- **底部**：红 HP 球、蓝 MP 球、中央圆形菜单、1–6 物品槽、技能槽。
- **左侧**：掉落/经验消息流（`获得[物品]1个`、`获得 60 点经验值`）。
- **右侧**：常驻评分面板（`操作%`、`技巧%`、`被击数`、`评分`）。
- **任务**：底部任务追踪条。
- **聊天框**：客户端旧式聊天窗；内容是真实事件流（清房、领主出现、拾取、任务进度），
  不是假聊天。

**技能槽画 6+6 两行。** 录像只画 6 个（A S D F G H），本作有 12 个技能键
（A S D F G H Q W E R T Y），所以第二行照同样样式补 6 个。这是对录像的**有意偏离**：
不画第二行，Q/W/E/R/T/Y 在画面上就没有对应槽，同机位对照会在键位区露出破绽。

## 二、MP：本来就是一个真的资源

复核代码时发现 **MP 已经在 `core.js` 里**：`player.maxMp`、每个技能的 `mp` 消耗、
`player.mpRegen` 与回复都在跑，玩家卡上也有一条蓝条。所以这一项不是“新增系统”，
只是把**玩家卡的蓝条换成录像的蓝球**，数值与消耗照旧。蓝球接真实 `player.mp`，
不做常满假球。物品系统里因此仍要有 **HP 药与 MP 药**两种消耗品。

## 三、删掉本作附加 HUD

- 删：本作自己的评分面板、战斗日志、节奏线、操作提示。
- 战斗日志的内容搬进**聊天框**，不复活旧 HUD。
- 触屏键删；`CLAUDE.md` 的收工判据从「键盘和触屏两条路都通」改成「键盘路径通」。
- 键位：技能 A S D F G H Q W E R T Y、上挑 Z、觉醒 V、攻击 X、跳跃 C **全部不动**；
  **I 背包、L 任务、K 三页签面板（技能/装备/属性）、1–6 物品、Esc 关闭**；
  NPC 交互统一空格/上。

## 四、领主头顶名字：进入战斗/被攻击时显示

330s 帧上 Boss 头顶写着粉色「领主 - 暗咒猫妖」，是在玩家打它时出现的。
`ADR-0060` 原来写「头顶不写、脚下不画光环」；这篇改写为：
**进入战斗/被攻击时显示头顶名字；脚下仍不画影子/光环；目标条照旧常驻。**
常驻头字与脚下光环仍然不做——那是业主 2026-10-18 明确讨厌的。

## 实现记录（2026-10-24，第一遍）

**录像 HUD 的尺寸口径**：录像 HUD 是客户端 **800×600 版式 ×1.8**（底条 800×91 →
1440×164、槽 40×39 → 72×70、球 56×56 → ~101px）。录像坐标系是游戏画面
1440×1080；本作 HUD 用 `HUD_PX = 0.5` 折到 720×540。

量到的矩形（1440×1080 视频px，30s/330s 两帧一致）：

| 元素 | 矩形 / 几何 |
|---|---|
| 红 HP 球 | 球心 (52,993)，外框约 97×162（纵向椭圆） |
| 蓝 MP 球 | 球心 (1388,993)，在**右下角**，外框约 84×162 |
| 物品槽 1–6 | 每格 70×72，y 1000..1072，x 852/922/992/1062/1132/1202 |
| 技能槽 A–H | 每格 70×72，y 1000..1072，x 166/236/306/376/446/516；**录像只有一排** |
| 左上目标条 | 约 (10,50,340,75) |
| 右侧评分面板 | 约 (1150,665,270,185)，四行、行距≈36 |
| 右上小地图 | 外框 (1187,46,221,233) |
| 任务追踪 | 约 (600,930,375,85) |
| 左侧消息流 | 起点约 (30,94)，行距≈35 |
| 底部 HUD 总带 | y 912..1080，x 4..1430 |

**原件**：`assets/import_dnf_hud.py` 从 `sprite_interface2_hud.NPK` 的 `hud.img`
f0（底条）、f1/f2（红/蓝球液体）、f77（槽框）、`menu_icon.img` f1（菜单）、
`sprite_interface2_quest_mission.NPK` 的 `mission.img` f0（任务条）、
`sprite_interface/chatting.img` f0（聊天框）烘成 `assets/hud.png` + `hud.json`，
表是 `render.js` 的 `HUD_UI`。

**已做**：底部客户端的 HUD 条、红/蓝球（液体按 `player.hp/mp` 裁剪）、1–6 物品槽、
中央菜单、任务条、左侧消息流、右侧常驻评分面板；玩家卡/房间卡/节奏线/操作提示撤掉；
**触屏路径整段删除**（`TOUCH_LAYOUT`、触屏键、`?touch=1`、触屏测试都删了；
指针只剩鼠标点选/拖拽），浏览器测试只跑键盘。
**横幅**：房名牌、`Enemy down`、`房间清空 · 门开了` 三行在 `00002` 里都没有，
已从深处删掉；关卡名（`stageTitle`）、升级/Buff/领主阶段保留。

**名字**：普通怪头顶不写名字（录像没有），只有领主成为当前目标时浮出；
玩家头顶加 `Lv.n 鬼剑士`（录像里是 `Lv.6 阿努纳奇`，本作取自己的职业名）。
底部补了一条细经验条 + `Lv` 读数（录像有，本作之前漏了）。
**深处调色**：`assets/grade_deep_forest.py` 把 set 02 烘成 `forest-deep.png`
（brightness 1.06 / contrast 1.12 / color 1.18），只在深处用；别的关仍是原图。
**同机位对照第一遍**：9 间路线房的进门帧与录像并排看过，结构（地图、房宽、
HUD 分区、怪种）对得上；剩余差异集中在场景亮度/布景密度/相机锚点，
需要业主实玩后按他的眼睛校准。对照图在
`tests/browser/artifacts/deep-compare-{1,2,3}.jpg`。

**调色**：同机位量游戏画面中央的平均亮度，录像 **50–77**、本作 **45–56**；
在**世界窗口**上压一层 `rgba(255,248,230,0.08)` 的暖白，HUD/黑边不动。
**不用 `ctx.filter`**：全屏 filter 在云机器上把帧率拖垮，deep 冒烟因此假红过一次。

**小地图默认圆形雷达**：`00002` 开场到 74s 前右上角是圆形雷达（只画相邻格与已探索格），
之后本作才切方形整图；所以 `mapMode` 默认 `"radar"`，`Tab` 仍切方形整图。
**同机位看 42 房那一帧时，雷达是默认形态**，方形整图只作为可选视图保留。

## 实现记录（2026-10-25，第二遍：底条逐格重量，物品与技能原来对调了）

上一遍表里那两行 `物品槽 x852..1272、技能槽 x166..586` **站不住**（前一组是绝对
1920 坐标、后一组是画面内坐标，两把尺子混用）。这一遍在**游戏画面坐标**（1440×1080，
从 x=240 起）上逐格量 `band-13.png` / `band-316.png`：

| 元素 | 游戏画面坐标 | 本作画布（720 宽，÷2 后 +120） |
|---|---|---|
| 物品槽 1–6 | x170..585，y1000..1072，每格 ≈69×72 | x205，格宽 34.6 |
| 中央圆盘 | x600..820，C 按钮约 50×50 | x420..530（**暂缺原件**） |
| 技能槽 A–H | x860..1295，y1000..1072，每格 ≈72×72 | x550，格宽 36.25 |
| 任务条 | x890..1210，y930..975 | x565，y424（让开第二排），160×24 |
| 等级卡 | “Lv.6” x160..215；绿经验条 x260..390，y969..989 | 文字 x200；条 x250..315，y484..494 |

- **对调的两排改正了**：上一遍把物品槽画在录像技能槽的位置、把技能画在录像物品槽
  的位置（`drawItemSlots` 在 546、`BAR.x` 在 203）。现在按上表落位。
- **槽框不叠了**：`mainhud.img` f77 是一颗**绿宝石**（镶嵌槽），不是空槽；底条
  `hud.img` f0 本身自带两排凹槽，所以空槽就露底条。键位字母 1–6 / A–H 改到**槽底
  正中**的小字（录像如此）。
- **经验条搬回等级卡**：录像的绿条在底条左侧（x260..390 / y969..989），不是屏幕
  最下面那条 3px 细线。
- **任务条底图暂时自己画**：这个客户端版本里找不到录像那条「任务」横条的原件
  （`mission.img` 是竖面板、`battledungeon.img` f0 写「戰場列表」、`quest_tag.img`
  是任务类型标签），先画同位置的深色横条，等原件找到再换。
- **中央圆盘暂时不画**：`menu_icon.img` 在这个版本是带中文标签的方按钮（个人情报/
  物品栏/任务…），f1 只是青色高亮框；画上去会出现录像里没有的青色方块。底条自带
  的 SP 位先留着。
- **关卡名位置**：`TITLE_POS` 那一套走的是世界变换，早先写 305 实际落在 351；
  按 00002 的 13s 帧（两行字视频 y530..650、重心 295）反算成 **217**。
- **评分那一行写数字**：录像四行是 `85% 操作 / 57% 技巧 / 0 被击数 / 55 评分`，
  本作原来第四行写的是 S/A/B 档位；现在跑图里写 `rating.score`，档位只留给结算页。

**尚未**：聊天框在城镇已画、跑图里仍是左侧消息流；录像技能槽只有一排，
本作按 6+6 两排放，第二排在录像那一排**之上**，这是对录像的有意偏离。
领主条已按 `00002` 改成**从头就是红条**（`barColor: "red"`），不再走绿→红相位。

**2026-10-27 盘点，还差这几块（都还没动手）**：

| 缺什么 | 卡在哪 |
|---|---|
| **中央圆盘** | 这个客户端版本没有录像那个圆盘原件（`menu_icon.img` 是带中文标签的方按钮），暂不画 |

## Consequences

- HUD 从“本作自己的布局”整体重画；旧的 `drawHud`/`drawSkillBar`/`drawTargetPanel`/
  `drawBossTargetPanel`/`drawMinimap` 要按 50% 录像坐标重排，12 槽改 6+6。
- 评分/日志/节奏线/提示删除后，依赖它们读数的浏览器断言改成读 `state`。
- 触屏测试删除；`CLAUDE.md` 与 `npm run test:browser` 的说明同步改。
- 新增 `town.png`/`npc.png`/`gui.png`/`items.png` 四套烘焙与 atlas；
  城镇与系统 UI 的验收标准改为“与客户端原图一致”，不再叫逐帧对照。
- 领主头顶名字的出现条件要单独测：进战斗前不画、被攻击后画、脚下始终不画光环。
