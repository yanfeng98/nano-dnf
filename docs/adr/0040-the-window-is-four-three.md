# 世界收进 4:3 的窗口 —— 画布、窗口、房间是三个宽度

**Status**: accepted（2026-10-14）。业主在 grill 上答 **Q1 选 a**（这一片就收掉那 33%）、
**Q4 选 (a)+(b)**（桌面纯黑、触屏按键进黑边）、**Q5 选 a**（只有游戏世界收，菜单仍满屏）。

## 决定

**一、画布仍是 960×540，世界只画中间 720×540。**

720×540 正好 4:3。按 `CAMERA.zoom` = 1.5775 算，一屏于是装
**720 ÷ 1.5775 ÷ 84 = 5.434 身位**，与录像的 1440 ÷ 265 = 5.4340 一模一样。
左右各 120 px 是**纯黑**，**明着填一次**（不是指望画布底下那层 CSS）：抓帧、分享图，
以及"世界有没有画进黑边"这种东西都要它一定是黑的。

**二、三个宽度从此分开。**

| | 是 | 谁读 |
| --- | --- | --- |
| `ARENA` | **画布** 960×540 | HUD、暗角、全屏界面 |
| `VIEW` | **世界窗口** 720×540、`left` 120 | `windowWidth()`、死区、世界那一趟的裁剪与偏移、HUD 的左右边距 |
| `ROOM` | **一间房的默认尺寸** 960 | `roomWidth/roomLeft/roomRight` 的回落、铺背景 |

在这之前 `ARENA.width` **一数两用**：既是"屏幕多宽"又是"默认那一间房多宽"，
而所有房间的 spec 都没写 `width`。照字面把 960 改成 720 会**顺手把每一间房也缩成 720**
—— 一屏一间，`docs/adr/0035` 整条作废。所以必须先拆，再收。

**三、世界那一趟加一段裁剪与偏移。**

`ctx.clip()` 到窗口矩形，再 `translate(VIEW.left, 0)`；裁剪压在屏幕震动**之前**
（晃的是世界，窗口不动）。房名牌本来就要把世界那一趟的变换倒退回去，现在多退一段
`-VIEW.left` —— 不补这一行，那块字会偏到黑边里去。

**四、菜单不收。**

标题、暂停、通关、地区地图仍是满屏 16:9：它们是**本作自己的**，录像一个字没说，
把菜单也锁进 4:3 是拿录像当挡箭牌扩权（而且地区地图那张 `region.png` 是照 840 宽量的）。
全屏界面画在黑边**上面**，所以黑边只在游戏里出现。

**五、黑边里放什么。**

桌面：什么都不放，纯黑，与录像一致（它的 HUD 一律压在游戏画面里）。
**触屏那一路**：按键挪进黑边 —— 那是录像给不出答案的地方，而空着的 25%（左右各 120 px）
在手机上就是白白浪费的拇指区。

## 为什么

录像的游戏画面是**居中的 4:3**：1920×1080 的帧里，游戏占 x 240..1679（1440 宽），
左右各 240 纯黑。本作收之前一屏 960 ÷ 1.5775 ÷ 84 = **7.245 身位**，比录像多看得见 **33%**。

这一条是 `adr/0035` 的收尾：那一片把**远近**（zoom）量对了，但画幅还是 16:9，
于是"一屏能看多宽"仍然比录像宽出三分之一。`adr/0035` 的「代价与未决」里写着
"那 33% 单开一片"，就是这一片。

## 代价与未决

- **HUD 与触屏整套重排**：所有按 `ARENA.width` 靠左/靠右摆的东西，边距改从**窗口**的边量
  （左边 `VIEW.left + m`、右边 `VIEW.left + VIEW.width - m`）。**以 480 居中的东西天然不动**
  （120 + 720/2 = 480）—— 提示条、强化卡、胜负画面、地区地图、标题全在这一档，省掉一批重排。
- **一批测试要跟着改**：镜头远近与死区那两条（`windowWidth()` 与死区的边都量在窗口里）、
  触屏按键那几条（起点/终点/不重叠/空白处）、地图窗口贴右边那一条。
- **`ARENA.leftWall/rightWall` 改了名**（变成 `ROOM.*`）：它们是**默认那一间房**的墙，
  不是画布的边；`attract.js` 与测试里共 14 处跟着改。
- **黑边与触屏的关系还没定死**：这一片先把按键挪进去，手机上真正的排法要等他实玩。
