# 雨是客户端那层天气：每个房间、两层雨丝、落地有溅点

**Status**: accepted（2026-10-19）。业主在 grill 上说「每个房间都下雨，比如 1:10 的界面」，
并选了「轻雨 + 两层 + 溅点 + 雨声」。

## 参考里量到的

- 整段录像的**帧差**（相隔 1/30 秒的两帧，放大 20 倍）在 1:10、2:30、4:10、5:00 都出现
  **满屏细而斜的雨丝**。把 1:10 的 7 帧取时间中位数再减掉背景之后，最长的几条是
  **128–174 视频像素高、角度 99–102°**（从 +x 量，即**顶部偏右 / 底部偏左**，离竖直约
  **10°**）。静帧里几乎看不见 —— 前几版只对着静帧找，所以漏了；这次是业主指了 1:10
  才回头量的。
- 客户端的效果图就是 `sprite/map/rain.img`（5×43 的白色细条，两帧）与
  `sprite/map/raindrop.img`（7 帧溅点）；雨声是 `sounds/amb/amb_rain_01..03.ogg`。
- 参考里普通房、走廊和 Boss 房都下；标题 / 地区地图 / 过关画面不下。

## 决定

- **每个副本房间都下**（正房、走廊、Boss 房），不参与判定；标题、地区地图、过关画面不下。
- 用客户端那两张图，画在**背景之后、人和布景之前**，**屏幕空间**，不随镜头滚动。
  （见下面的追记：画在人身上会让人物跑动时"闪闪的"。）
- **两层**：远层小 / 暗 / 慢，近层大一点 / 亮一点 / 快；960×540 上约 **80–100 条**。
  按 960×540 折，近层雨丝约 **70 px**、远层约 **40 px** 长。
- 落地有**淡淡的溅点**（`raindrop.img` 的 7 帧），不参与判定。
- 雨声循环 `amb_rain_01.ogg`（频谱最接近 1:10 那段），压在音乐下面；进房间淡入、
  离开 / 过关淡出。
- 雨丝**顶部偏右约 10°**、往左落，与参考的 99–102° 一致。

## 追记（2026-10-19 实玩）：方向反了，而且不该盖在人身上

业主实玩后说：「雨好像参考视频是斜的；人物跑起来闪闪的不对」。两条都量了：

- 第一版是 `angle: -0.10`（**顶部偏左**）——参考是 **99–102°**，也就是**顶部偏右**；
  方向反了，而且第一版只有 42 px 长，参考最长 128–174 px（1080p）。
- 第一版把雨画在**世界之后、HUD 之前**，近层会从跑动的人物身上扫过；在 14 fps 的
  跑动帧上读起来就是"人物在闪"。现在雨画在**背景之后、人和布景之前**——背景上仍是
  斜雨，人和怪保持干净。

## 被否掉的

- **只做雨声不做雨丝**：业主说的“每个房间都下雨”指画面。
- **一层贴图**：参考里雨丝有前后大小差；一层会像一张纸。
- **雨声用合成器**：客户端的雨声就是原素材，和音乐同一条来路。
