# 全作只有这一招的长度由你决定

## Status

accepted（2026-10-04）。业主在 grill 的 Q3 上点名选了 B：**「按住——松手即收，最长 3.13s」**，
推翻了我给的"固定长度"建议。

## 决定

**嗜魂封魔斩的时长不是一个数，是一段可截断的时间线：**

| 段 | 秒 | 参考帧 | 能不能截断 |
|---|---|---|---|
| 起手（起手闪 → 抬剑 → 掌心血球 → 铺开成漩涡） | **0.867** | `#33–#58` | **不可跳过** |
| 漩涡稳态（每一帧都可松手） | 0 – **3.133** | `#59–#152` | **松手即断** |
| 收势 | 0.133 | `#153–#156` | 固定 |
| 终结斩（举剑 → 挥下） | 0.133 | `#157–#161` | 固定 |
| 金色巨叉 | 0.267 | `#162–#170` | 固定 |
| 余晖 | 0.200 | `#171–#176` | 固定 |

- 起手 0.867s 走完之后，**每一帧松手都算数**：从参考 `#153–#156` 那 0.133s 的收势接进终结斩。
- **不松手到 3.133s 自动收**。这个上限不是估的，是参考里稳态那一段 `#59–#152` 的实测长度。
- 所以最短一次 = 0.867 + 0.767 = **1.63s**（一按就松，漩涡只闪一下），最长 = **4.77s**。

**松手不减终结斩的伤害。** 参考给不出"吸得越久越强"的任何证据，加一个它就是我自己发明的机制。
长短的差别只体现在**漩涡少跳了几拍**（每 0.300s 一拍，那是把稳态那 94 帧做自相关量出来的翻搅周期，
lag 9 帧处差值最小）——它自己就是代价。

## 为什么这一条要写下来

全作其余 12 条技能都是"按一下走完一整段"：`duration` 是一个数，`skillTimer` 从它倒数到 0。
**这一条是唯一的例外。** 不写下来，下一个人读到 `duration` 会照着老意思去用它。

## Considered Options

> **固定 3.133s，按一下走完。** 否，业主点名要按住。我原来的理由是"全作其余技能都是按一下走完、
> 按住会给输入层加一条只有它有的规则"——他知情之后仍然选了按住，所以那条规则就该存在。
>
> **松手即收，且吸得越久终结斩越强。** 否。参考给不出证据（见上）；而且它会把"该按多久"变成一道
> 要算的优化题，而这一招该有的读法是"吸住一片、看准时机收"。

## Consequences

- `SKILLS.bloodyRave.duration` 从"整段长度"变成**上限**；起手与收势的秒数另立字段写清楚，
  不再靠 `activeFrom` / `activeTo` 那两个比例字段猜。
- **输入层要新增一条**：施法期间如果 `input.skills[id]` 掉线（键盘松手 / 手指抬起）且在起手之后，
  提前结束这一招。**两条通路都已经撑得住**，不用新造一层：键盘按住时持续给 `input.skills`；
  触屏 `pointerdown` 落在技能格上会置 `held[slot] = true`、`pointerup` 才清
  （`src/main.js:613` 与 `:851`）。这一条**要有测试钉住**——否则触屏会悄悄退化成"按一下就放满 4.77 秒"，
  而按仓库的收工判据，键盘与触屏两条路都得通。
- **它撞上「定身」但不动它**：`CONTEXT.md` 的定身说"出招期间移动、跳跃、再出手都被拒绝"，这一招照旧
  ——**松手只结束这一招，不还手也不还站位**，朝向仍然在起手那一刻锁死。
