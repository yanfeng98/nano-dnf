## 需优先验证的评分文字

render.js约9029行把录像“SS”解释成“55”，目前画rating.score数字。
旧ADR0041曾记录4→5次被击时从SS降到S，与该解释冲突。`newresult/result2_mainhud.img`
恰含SSS/SS/S等白色等级字形，应对原录像裁片进行模板比较，排除数字5的误读后再改。

## 第二十四批：固定本局结算评分

本批只修复数据稳定性，不将当前评分公式、界面或时序认定为符合录像。

确定性复现：创建一局，将时间置于360秒、被击数3、攻击10次命中8次，进入胜利或失败；
随后只推进600帧。旧实现的评分82降到81，说明展示时间被计入战斗时间。
新实现于胜负首次确定时保存冻结的`resultRating`，`ratingOf`后续返回该快照。
失败可能发生于同一帧后半段，因此帧尾也记录首次结束状态，避免下一帧才取统计。
新局仍使用实时评分，未改变当前公式与奖励数值。

回归分别覆盖胜利与失败：等待不变、后续统计和等级变化不改写已结束结果、新局独立。
命令：`node --test --test-name-pattern='keeps the result rating stable' tests/core.test.js`。
修复前两项失败，修复后两项通过；完整单元测试324项通过。
