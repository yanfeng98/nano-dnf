## 2026-09-19 技能预览视频已破解

客户端每个技能都带一段官方预览视频（`Video/<职业>/<技能英文名>.avi`）。它外面套的是
「Neople Video File」容器，**不是真加密**：

- 前 32 字节是文件头（含明文长度），随后 **1024 字节明文**；
- 之后每个字节 = 明文自身 **异或 1024 字节前的明文**，所以可以从头迭代解出全文件；
- 解开后是普通 AVI（MPEG-1，160×90），可正常解码。

已用 `assets/decode_skill_videos.py` 把鬼剑士全部 **84 段**技能视频解密并导出到
`assets/dnf_src/skill-videos/`：每段一个 `.mp4`（可直接播放）+ 一张带帧号的
`<名字>.png` 全帧图 + `INDEX.txt`。

对照结论（与业主描述一致）：

- `HopSmash`（崩山击）：0-13 起手抬剑 → 14-27 前跃砸地、火焰冲击 → 28-49 蓝色冲击波
  → 50-57 收招。
- `GoreCross`（十字斩）：0-14 挥砍 → 17-33 十字成形并**向前推出** → 34-41 收招。

## 2026-09-20 特效包调色板与地面锚点（业主：「怒气爆发和崩山裂地斩的特效不对」）

复查结论：**包没选错，是烘焙方式错了**。客户端自己的预览视频把两个技能钉死了——
`BloodBlast`（怒气爆发）是原地插剑、脚下炸开血环、血柱从圈里升起；`OutRageBreak`（大蹦）是起跳、
砸地、裂缝张开、血气喷发。视频里的身体动作也正好对上这两招的行为（自身中心多段浮空 / 起跳砸地），
所以 `blastblood = 怒气爆发`、`outragebreak = 崩山裂地斩` 维持不变。

### 四个真正的原因

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 大蹦「更乱」，看不出巨剑和裂缝 | `PICKS` 用通配符 `*` 拉整个包，而包里**同一套图形按色板存了三份**：无前缀（素色）、`(tn)`、`(18)`。崩山裂地斩烘了 **29 层**，其实只有 9 个形状，红 + 橙 + 橙叠在一起 | 一次只取一个色板；`*` 只展开当前色板；`_ldodge` / `_dodge` 这类同形状条目按名字点名 |
| 颜色也不对（业主第二次反馈） | 上一轮按「红色怒气圈」的文字描述保留了**素色（红）板**，而客户端实际播的是 `(tn)` 板 | 两行改取 `(tn)`（怒气爆发白金、大蹦橙火）；只有包里只存在素色版的 `blood_floor.img` 单独保留红色 |
| 两个特效都「不像那一招」 | 合成时短图层取模循环，6 帧的血环在 13 帧合成里重播两三次，合成帧是客户端从未出现过的一瞬间 | 所有图层按同一条时间轴取样（第 i 帧取各自的 `i/(n-1)`） |
| 怒气爆发的血柱飘在角色左上方，不在脚下 | 包内图层共用客户端坐标，**角色站在包自己的血环中心**，不是包围盒中心；居中摆放等于把整块特效平移了 | `PICKS` 声明 `anchor`（血环 / 裂缝的中心），烘图时锚点落在格子地面线（75%），渲染时该线对到角色脚下 |
| 大蹦没有「血气巨剑」 | `outragebreak_bloodsword_none.img` 原生只有 20×44，客户端靠技能动画数据放大，导出不带这份缩放 | 该图层按**落地中心**放大 5 倍再合成；其余图层保持原比例 |

## 2026-09-21 大蹦分阶段：这一包是四组图按先后播（业主：「这个技能应该是多个技能特效组合的」）

**四组**图，客户端是分阶段放的。逐条拆开（`assets/dnf_effect_anim/rift-outrage-break-layers.png`、
同名 `.txt`，生成脚本 `assets/make_rift_layer_plan.py`）：

| 组 | 条目 | 帧 | 画的是什么 |
| --- | --- | --- | --- |
| 血剑 | `outragebreak_bloodsword_none.img` | 20 | f0-15 火刃从左上斜劈下来，f16-17 砸进地面炸开，f18-19 收成贴地火焰 |
| 地裂 | `outragebreak_floor.img` | 11 | f0 岩土碎裂夹红熔纹，f1 黑裂纹，f2-6 熔岩环由小到大，f7 碎石飞起，f8-10 裂纹贴地蔓延 |

| 点缀 | `bloodsexp_glow`(2) / `drops_1`(6) / `drops_2`(7) / `part`(5) | 20 | 砸地补光与星芒、岩浆滴落地摊开、碎岩与火星 |

**29 个条目 = 8 种图 × 3 条色板**（`plain` 血红 / `(tn)` 橙火 / `(18)` 与 `(tn)` 逐像素相同），
再减掉 4 条没重发的（`part` 与血剑压暗版的 `(tn)/(18)`）。`*_ldodge` 是同一形状的压暗孪生图
（总不透明度只有亮版的 1/4），出口不用。**色板只取 `(tn)`**，这是客户端预览那一版。

**播放顺序**（客户端预览 `OutRageBreak.avi` 100 帧 @30fps，0 = 砸地那一下；热像素计数：
f24-31 冲到 1500+，f32-59 掉到 100-180 只剩地上的环，f60-93 冲到 7800+）：

| 时间 | 画什么 |
| --- | --- |
| 0.00-0.20 | 血剑落下（行从落地前 0.2s 开始，剑砸在 `activeFrom` 那一下） |
| 0.00-0.07 | 补光闪一下 |
| 0.00-0.93 | 地裂：碎裂 → 熔岩环铺开 → 碎岩飞起 |
| 0.10-0.60 | 第一波矮宽火丛 |
| 0.30-1.98 | 熔岩环留在地上、裂纹贴地蔓延（空档期只剩这两样） |
| 1.15-2.30 | 第二波：细高岩浆柱 + 补光 + 火丛，最后散成火星 |

落点：血剑炸在**环心左边**（x204-343），岩浆从**环心右边**喷出来（x371-518）——客户端里人站
在环心，所以火是往他身后窜的；`part` 的帧坐标在包原点，客户端当粒子撒。

实现（`assets/import_dnf_effects.py` 的 `stages` 模式 + `FRONT_ROWS`）：

| 行 | 内容 | 画在哪 |
| --- | --- | --- |
| `mountainRift`（45 帧） | 血剑 + 地裂（4 段窗口：碎裂 / 环 / 环留住 / 裂纹） | 角色**身后**（技能行） |
| `mountainRiftFire`（45 帧） | 补光、两波火、岩浆滴、碎岩（10 段窗口） | 角色**前面**（`FRONT_ROWS`，`drawPlayer` 之后画） |

两行共用**一个窗口、一个缩放、一个锚点**（烘焙器的 `match` 字段把技能行的窗口传给前排行），
否则火就不从裂口里出来。`duration` 1.05 → **2.0s**、`activeTo` 0.95 → 1.95、`hits` 2 → **3**
（剑落 / 地裂研磨 / 第二波），`leapFrom` 0.12 → 0.07（跳跃本身没变，只是提前起跳好落在同一个
0.72s），冲击波跟着**第一下**（新增 `shockwaveHit`，默认仍是最后一下）。

实机逐帧：`node tests/browser/capture-effect.mjs mountainRift 30 0.12 500` —— 起跳阶段地上空的、
0.30 血剑扫过砸开地面、第一波橙火、0.70 只剩环与裂纹、0.78 第二波冲起来、1.0 散成火星环还亮着。

### 2026-09-21 业主看片后的两处（「好像地裂圈有点小，然后什么好像需要再次优化」）

量过之后确认业主没说错：包里画得最大的那道环是 239px 客户端画布，出口成 **232px**；这一招自己的
半径是 190（直径 380），客户端的裂缝占它屏幕约 60%。所以**整块地面**放大 1.8x，并把 `size`
480 → **840**（`dy = -210 = -size/4`，锚点才还在脚底）——放大地面会撑大窗口，`size` 随窗口一起
放大，因此**只有地面那几层真的变大**，剑和火维持业主已经点头的大小：
